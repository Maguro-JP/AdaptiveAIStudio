# コーディングに使えるモデルの比べ（2026-10-31）

使う人と同じ道（`scripts/check-user.mjs`）で比べた。配る形を起こし、画面から次の 2 つを頼み、出来たファイルを node で動かして判定する。

1. fizzbuzz.js を作る（1〜15 を Fizz / Buzz / FizzBuzz で出す）
2. 引き算になっている calc.js の add を足し算に直す（動かして 5 が出るか）

機械はこのコンテナ（Linux、CPU 4 コア、記憶 15GB、GPU なし）。量子化はどちらも Q4_K_M。

| モデル | 大きさ | 先読みあり | 先読みなし | 2 つにかかった時間（先読みなし） |
|---|---|---|---|---|
| Qwen3.5-4B | 2.7GB | 通る回と落ちる回があった（`let i = 15` と書いた回、ファイル名を fizz.js にした回） | 通った | 457 秒 |
| Qwen3.5-9B | 5.7GB | 2 回とも落ちた（どちらも `for (let i = 15; …)`） | 通った | 1498 秒 |

## 分かったこと

- 落ちていた主な原因はモデルの力ではなく、先読み（InputLookupTokenPredictor）だった。頼みの文にある「15」を答えに混ぜていた。先読みを外すと、どちらも 2 つとも通った（DECISIONS 202）
- 4B は 9B のおよそ 3 倍速い。CPU だけの機械では、4B を推奨のまま残す
- 9B は記憶が 16GB 以上あり、時間をかけてよい人向け。画面の「設定 → モデル」から選べる

## まだ確かめていないこと

- Windows の CI（setup.exe を入れた形）で、先読みを外した版を通すこと
- GPU のある機械
- 2 つより大きい仕事（複数のファイルにまたがる直し、試験を書かせる）
