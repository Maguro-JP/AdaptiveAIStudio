# ブロックでつくる画面の速さ（2026-11-08）

ブロック 200 個（くり返す 1〜100 の中で、計算 198 個を一列につなぎ、最後に表示）を `.blocks.json` で開き、
Playwright（Chromium、1600×1000）で押して測った。3 回の真ん中の値。Playwright の往復の時間を含む。手元の Linux の開発の本体（`npm run ui`）で測った。

| 測ったもの | 直す前 | 直した後 |
|---|---|---|
| 開く（押してから描き終わるまで） | 609 ミリ秒 | 330 ミリ秒 |
| ブロックを引く（マウスを 1 回動かすごと） | 25.6 ミリ秒 | 16.9 ミリ秒（画面を描く回に一度） |
| 引いて離す | 384 ミリ秒 | 16 ミリ秒 |
| ▶ 動かす（押してから結果まで。2 万回の手順） | 348 ミリ秒 | 150 ミリ秒 |
| 欄を書き換える（JavaScript を作り直す） | 51 ミリ秒 | 41 ミリ秒 |
| 整える | 438 ミリ秒 | 150 ミリ秒 |

## 遅かった所と直し方

- 描くとき、ブロックを一つ入れるたびに大きさを読んでいた（読む・書くの交互で、200 回並べ直していた）。全部を入れてから一度に読み、そのあと口を置く
- 線の両端を、毎回 DOM を探して位置を読んでいた。口の位置はブロックの中で変わらないので、描くときに一度だけ測って覚え、ブロックの位置に足す
- 引いている間、動くたびに線を全部描き直していた。画面を描く回（requestAnimationFrame）に一度だけ、動かしたブロックに付く線だけを描き直す
- 離したとき、全部を描き直していた。位置は引いている間に書いてあるので、描き直さない
- つなげるかの判定は型の組で決まるので覚えておく（線を引く間、口の上を通るたびに聞かれる）

作り直す JavaScript（compile）は 200 個で数十ミリ秒に収まったので、変えた所だけ作り直す仕組みは足していない。

測り方の台本は残していない（作業用の一時の場所に置いた）。同じ形の 200 個を作り、開く・引く・動かす・書き換える・整えるを順に押して、時間を取った。
