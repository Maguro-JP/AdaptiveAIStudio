# 実現計画（改訂版）

初版の設計は「制限で止まらないチャット基盤」に寄っていた。
本来の希望は **「Cursor からクラウド依存を外し、複数のローカルモデルに
役割分担させて動かす個人用開発環境」** なので、こちらを正とする。

---

## 1. 到達目標

```
クリックで起動
   ↓
Cursor 相当の開発環境
   ↓
指揮AI が作業を分解し、得意なモデルへ割り振る
   ↓
日本語会話担当 / コーディング担当 / レビュー担当 / 画像・デザイン担当
   ↓
ファイルを読み・書き・テスト実行して、実装が進む
```

クラウド(Claude API)は「使えるときに使う上位の頭脳」であり、
無くても開発が止まらないことを常に維持する。

## 2. 現状との差分（正直な評価）

| 希望 | 現状 | 差分 |
|---|---|---|
| モデル切替・制限で止まらない | **実装済み** | なし |
| Claude を API で利用 | **実装済み**(公式SDK) | なし |
| ファイルを読み書きして実装が進む | **未実装** | ここが本体。最大の差分 |
| 複数モデルへの役割分担 | **未実装** | Router はあるが「フォールバック用」で、得意分野で選んでいない |
| 指揮AI / サブエージェント | **未実装** | 全面的に未着手 |
| クリック起動 | **未実装** | 現状は `npm run chat` |
| 画面 | **未実装** | 現状はCLIのみ |

つまり現時点で完成しているのは **土台の配管** であって、
体感できる価値（コードが書かれる）はまだ1つも出ていない。

## 3. 方針

### 3.1 エージェントを最優先にする

チャットUIより先に **ツール実行ループ** を作る。
「LLMがファイルを読み、差分を提案し、承認を経て書き込む」が動けば、
UIが素朴でも開発は回る。逆にUIから作ると、綺麗な画面で雑談するだけになる。

必要なツールは最小4つ。

| ツール | 役割 |
|---|---|
| `read_file` | ファイル読み取り |
| `list_files` / `search` | 探索 |
| `write_file` | **差分プレビュー + 承認必須** |
| `run_command` | テスト・ビルド実行(許可リスト方式) |

ローカルモデルでのツール呼び出しは、OpenAI互換の `tools` が
使えるモデル(Qwen2.5-Coder 等)を前提とし、
非対応モデル向けにテキストプロトコル方式のフォールバックを用意する。

### 3.2 組織として動かす（役割分担）

単なる「得意分野でモデルを選ぶ」ではなく、**会社の組織構造**として設計する。

- 窓口が依頼を言語化し、統制へ上げる
- PM が分解し、各部署リーダーと相談し、ユーザーと詰める
- 部署リーダーが作業者へ割り振り、**複数の作業者が並列で働く**
- 検査を通し、統制が検収してユーザーへ返す

職能（何をする人か）とモデル（人材）を分離し、
配置は設定ファイルで自由に変更できるようにする。

並列度は「同時にロードするモデル数」ではなく
**「同一モデルへ同時に流すタスク数」** で稼ぐ。
VRAM 8GB でモデルを増やす方向は行き止まりになるため。

詳細は [組織設計](ORGANIZATION.md) を参照。

### 3.4 起動はクリック1回

配布形態は Tauri のインストーラ(`.msi`)。

- インストールするとスタートメニュー / デスクトップにアイコンが出る
- 起動すると Core Daemon が常駐し、UIが開く
- Ollama が起動していなければ自動で起動を試みる

開発中は `npm run chat` のままでよいが、
Phase が進んだ時点で **クリック起動を満たさない状態を「未完成」とみなす**。

### 3.5 Claude Code CLI 連携

`claude` コマンドを **1つのProviderとして扱う**。
HTTPではなく子プロセスとして起動し、標準入出力で会話する
`claude-cli` アダプタを追加すれば、API課金とは別枠で
既存のClaude Code契約をそのまま使える。

契約 (`ChatProvider`) は既に「HTTPである」と仮定していないので、
この追加でアーキテクチャを変える必要はない。

## 4. 改訂フェーズ

| Phase | 内容 | 完了条件 |
|---|---|---|
| ~~P0~~ | ~~Provider層・フォールバック・CLI~~ | **完了** |
| **P1** | ツール実行ループ + 4ツール + 差分承認 | ローカルモデルが自分でファイルを読み、修正差分を出し、承認後に書き込める |
| **P2** | レーン制御 + スケジューラ + 並列作業者 | 同一モデルで作業者3名が同時に別ファイルを実装できる |
| **P3** | PMによるDAG分解 + 部署リーダー + 検査 | 1つの依頼が自動で分解・並列実行され、検査を通る |
| **P3.5** | 窓口・統制 + 承認ゲート3箇所 | 曖昧な依頼から検収まで組織として一周する |
| **P4** | `claude-cli` アダプタ | API課金なしで Claude Code を担当として使える |
| **P4.5** | 実行可能性プランナ + llama.cpp直接制御 | VRAMに載らないモデルを部分オフロード/mmapで起動できる |
| **P5** | Tauri デスクトップUI(チャット + 差分ビュー + 役割表示) | クリック起動して、誰が何をしているか見える |
| **P6** | インストーラ(.msi)配布 | 自分のPCに入れて日常利用する |
| **P7** | Project Memory / 独自ワークフロー | 毎回ルールを貼り直さなくてよくなる |

**P1 が最重要。** ここが動くまで、他は着手しない。

## 5. 明確に「やらない」こと

- 完全なCursor互換(エディタ本体の実装)。既存エディタと併用する前提とする
- 画像生成モデルの学習・ファインチューニング
- 複数ユーザー対応・SaaS化
