# 考え直す

配った先で、押しても何も起こらない状態が続いた。直したのは毎回その1件で、
次の週にはまた別の場所で同じことが起きている。1件ずつ直しても止まらない
ということは、直す場所が違う。ここは、何を作っているのか・何が足りないのかを
決め直すための頁。

## 1. これは何をする道具か

`README.md` の一行目はこう書いてある。

> LLMを動かす場所ではなく、AIが動く場所。

言い直す。手元の機械だけで、コードを直させる場所。

そこから出てくる決め手は一つ。使う人は、自分の機械の前に座っている。
繋がらないときも、遅いときも、読めないときも、その人しか居ない。
こちらが後から記録を読んで直す形は、この道具では成り立たない。

## 2. 何が起きていたか

出た不具合を並べると、別々の話に見える。

| 出方 | 場所 |
|---|---|
| 押しても一行も出ない | doctor |
| 動かし方の一覧が空で、何も選べない | 設定 |
| 送ったのに何も返らない | 会話 |
| 案内の通りに開くと、その欄が無い | ファイル |

全部、同じ形。待っているものが返ってこないときに、
画面が何も言わない。原因はどれも次の三つのどれかだった。

1. 全部揃うまで出さない（doctor の表・設定の頁）
2. 待ちに上限が無い（保存先を読む・繋ぎ先を叩く）
3. 拾い手のいない例外が、外へ落ちる（`void f()`・`onclick`）

## 3. なぜ、そういう作りになったか

「止まらない」を、繋ぎ先の話としてだけ読んでいた。

この道具の思想は、外の都合（制限・障害・提供終了）で止まらないこと。
それは実装できている。落ちたら別のモデルへ移るし、外が無くても動く。

その一方で、内側が止まったときに何が見えるかを、一度も設計していない。
待つ側の作りは全部「返ってくる前提」で書かれている。返ってこない道は、
繋がっていないドライブ・必要になるまで実体を持たない置き方・数GBの読み込みなど、
配る先では普通にある。ここで確かめている限りは、どれも一瞬で返る。

## 4. 決め直す

### 4.1 「止まらない」の意味を、内側にも広げる

> 止まらないとは、止まったことが必ず見えること。

外の障害と同じ扱いにする。待つ所には、必ず上限と、待っている表示を置く。
黙って待ち続けるのは、落ちるより悪い（落ちれば分かるが、黙ると分からない）。

### 4.2 完成の定義を変える

いま `ROADMAP.md` の表は「配管が通ったか」で埋めてある。だから全部
「実装済み」なのに、開いても何もできないという状態が起きた。

> 完成とは、配る形で・配る機械で・1ターンできたこと。

書けたか、試験が通ったかではない。この定義でしか、今日の状態を「未完成」と
言えない。

### 4.3 順番を、入口から積み直す

「エージェントが先、画面は素朴でよい」で進めてきた。土台としては正しかったが、
触るのは入口だけなので、入口が黙る状態では後ろが何であってもゼロになる。

積む順番:

1. 開いて、一言送って、返ってくる（何も設定していない人が、詰まらずにここまで）
2. 止まったら、止まったと出る（どこで止まっているかまで）
3. その先（分解・並列・組織）

### 4.4 画面の作法は、先行例に合わせる

会話に名前を付けられない、新しい話を始める場所が無い、といった形になっていた。
どれも、普通のチャットの道具には最初からある。説明の要る独自の形を作らない。

## 5. 足りないもの

機能ではなく、確かめ方が足りない。

この表は、埋まったら書き換える。埋まっていないことより、
埋まったのに「一度も無い」と書いたままの方が危ない（次に読む人が作り直す）。

| 足りないもの | いま |
|---|---|
| 配る形（bundle）のまま動かすテスト | 入れた（`npm run check:bundle`、2026-09-08）。組む → その中で全部のテスト → 画面を起こして送って返る → sweep → 止まるところまで |
| Windows で1ターンするテスト | 通った（CI の `bundle`、2026-09-16 JST）。上の一つを Windows で回し、送って返る（32 文字・43 秒）・sweep 不具合なし・止まるまで。重みは乱数の模型 |
| 本物のモデルで答えを見る | 通しているのは乱数の重みの模型。道が繋がっていることしか見ていない。製品が自分で言う形にはした（`npm run selftest` の「送って返る」）ので、配る機械で一度押せば分かる |
| 初めて開いた人の道案内 | 入れた（`/api/ready`、2026-09-08）。開いた時点で、使えないなら理由と次の一手を出す |

残っているのは、本物のモデルで答えを見ることの一つ。そこが埋まるまで、
「直しました」は「ここでは直りました」以上の意味を持たない。そう書く。
