# IDLE — 暇なら考える。ただし、無駄には考えない

## 0. 何が難しいのか

「暇なら考えて」は簡単に言えるが、放っておくと空回りする。

計算は無料でも、無料でないものがある。

> 無料なのは電気代であって、読む側の集中力ではない。

役に立たない提案が10件並べば、利用者は全部読まなくなる。
そうなった時点で、この機能は死ぬ。

だから「考えるかどうか」を、考える前に判断する仕組みが要る。
これはハーネス側の仕事。

## 1. 考える前に3つ問う

```
待機30秒
  ↓
1. 前提 — そもそも考える意味があるか（何か変わったか）
2. 予算 — この1時間、もう考えすぎていないか
3. 実績 — この考え方は今まで役に立ったか
  ↓
どれかで落ちたら、考えない（理由は残す）
```

選ばなかったことも結果なので、必ず理由を返す。
黙って何もしないと、壊れているのか休んでいるのか分からない。

```
次に考えること: なし（今は考える意味のあることがありません）
```

## 2. 二種類のきっかけ

考え始める理由は二つある。

| きっかけ | 例 | 判断 |
|---|---|---|
| 変化 | コードが変わった | 変わっていなければ考えない |
| 時間 | 今日まだ全検査を回していない | 変わっていなくてもやる |

前者だけだと、手を止めている日は何もしない。
だが実際には「今日まだやっていないこと」がある。

```
本日分の DAILY SWEEP がまだです
  [PATROL] 巡回検査 — WARDEN

CARRY-OVER の前回分が残っています
  [DIGEST] 通し確認 — CURATOR
```

## 3. 日課 (DUTIES)

時間で起きる仕事。済んだかどうかが記録される。

| 日課 | いつ | 何をするか | 逃した分 |
|---|---|---|---|
| DAILY SWEEP | 毎日 | 全体の検査を回す | 埋めない |
| CARRY-OVER | 毎日 | 前回以降の変更を通しで見る | 埋める |
| PLAN AHEAD | 4時間ごと | 提案と残作業を見て順番を決め直す | 埋めない |
| MORNING BRIEF | 毎日 7時 | 外の動きを確認する | 埋めない |
| WEEKLY REVIEW | 毎週 月曜 | 一週間の変更を振り返る | 埋める |

```
日課                  状態        次回
DAILY SWEEP         済み            7時間後
CARRY-OVER          済み            7時間後
PLAN AHEAD          済み            3時間後
MORNING BRIEF       済み            14時間後
WEEKLY REVIEW       済み            2日後

今やるべき日課はありません。
```

### 溜め込まない

逃した分を全部やり直そうとすると、朝から晩まで過去の埋め合わせになる。

だから埋めるのは直近の1回だけ。それ以上は流す。

- 「昨日の分の確認」は意味がある → 埋める
- 「先週の月曜の全検査」はもう意味がない → 流す

流したことも記録する。何度も流れているなら、その日課の設定が間違っている。

### 日課専用のモード

「前回分の確認」や「段取りの見直し」は、時間で起きるべきもので、
気が向いたときに勝手に始めるものではない。

これを区別しないと、日課専用のモードが常時発火して予算を食う。
`dutyOnly` を立てたモードは、日課からしか起動しない。

## 4. 思考モード

人が暇なときにやることは一つではない。

| モード | 何を考えるか | 担当 | 起動 |
|---|---|---|---|
| PATROL | 検査を回し、いま壊れていないか | WARDEN | 変化 / 日課 |
| RECON | コードを見回り、気になる箇所を探す | SCOUT | 変化 |
| RETROSPECT | 最近の変更を振り返る | CURATOR | 変化 / 日課 |
| FORECAST | この作りのままだと次に何で困るか | ARCHITECT | 時間 |
| BRIEFING | 外の情報を取りに行く | ENVOY | 日課 |
| WHAT-IF | 別のやり方を考えて比べる | ARCHITECT | 時間 |
| DIGEST | 前回以降の変更を通しで見る | CURATOR | 日課のみ |
| AGENDA | 次に何から手を付けるかを整理する | ARCHITECT | 日課のみ |

前提条件が要点。何も変わっていないのに考え直すのは、思考ではなく空回り。

外の世界は分単位では変わらないので BRIEFING の間隔は長い。
WHAT-IF は始終やられると邪魔なので、さらに長い。

実際の動作:

```
  [PATROL] 巡回検査 — WARDEN
  💡 [PATROL] テストが1件も無く、検査を実行できない

  [RECON] 見回り — SCOUT
  💡 [RECON] fetchUser が HTTP エラーを判定していない

  [RETROSPECT] 振り返り — CURATOR
    → 報告することはありませんでした

  [BRIEFING] 外部情報 — ENVOY
    → 報告することはありませんでした

  [FORECAST] 先読み — ARCHITECT
  💡 [FORECAST] 通信層が各所に散らばると差し替えが効かなくなる

  この1時間の消費: 10 / 12
  次に考えること: なし（今は考える意味のあることがありません）
```

「報告することはありませんでした」も正しい結果。
無理に何か言わせると、雑音が増えるだけになる。

## 5. 実績で配分が変わる

出した提案の数ではなく、採用された数で測る。
たくさん喋る人が役に立つとは限らない。

```
思考モード            実行  提案  採用  却下  採用率
PATROL                 8     6     5     1     83%
RECON                 12     9     2     7     22%
FORECAST               3     2     2     0    100%
```

`/do` で採用、`/reject` で却下すると、それがそのまま実績になる。
採用率の高いモードに時間が回り、却下され続けるモードは自然に減る。

ただし少ない判断で決めつけない。
判断が5件溜まるまでは、初期の優先度と混ぜる。
1回却下されただけで黙り込まれても困る。

## 6. 予算

1時間あたりの総コストに上限を置く（既定12）。
モードごとにコストが違う（検査は軽く、外部調査は重い）。

使い切ったら考えるのをやめ、1時間経てば戻る。

```
この1時間の消費: 10 / 12
```

未処理の提案が10件溜まっていても止まる。
利用者が追いつけていないのに考え続けるのは、置き去りにしているのと同じ。

## 7. 設定

```jsonc
{ "initiative": {
  "enabled": true,
  "idleSeconds": 30,       // 何秒待機したら考え始めるか
  "budgetPerHour": 12,     // 1時間に使ってよい思考の総量
  "maxOpen": 10,           // 未処理がこれに達したら止める
  "modes": ["patrol", "recon", "forecast"]  // 使う思考モード（省略時は全部）
} }
```

| コマンド | 内容 |
|---|---|
| `/idle` | 思考モードの実績と、次に考えること |
| `/duties` | 日課の状態（済み / 未了 / 待機）と次回 |
| `/skip <id>` | 今期の日課を流す |
| `/proposals` | 溜まった提案 |
| `/do <id>` / `/reject <id>` | 採用 / 却下（実績に反映される） |
| `/think` | いま考えさせる |

## 8. 原則

1. 考える前に、考える意味を問う。変わっていないなら考えない
2. 選ばなかった理由を残す。沈黙は情報にならない
3. 出した数ではなく、採用された数で測る
4. 少ない判断で決めつけない。1回の却下で黙り込ませない
5. 利用者が追いつけていないなら止まる。溜めるのは親切ではない
6. やっていないことが分かれば、変化が無くても有効に動ける
7. 逃した分は直近の1回だけ埋める。過去の埋め合わせで今日を潰さない
