## 2026-09-01  検証は社用PCでも続ける

**決めたこと**

| 場所 | どうする |
|---|---|
| 自宅 | インストーラで綺麗に入る。更新も、不要ファイルの削除も自動 |

  持ち込む方法ではなく、**その場で取ってくる**方法を用意する。

## 2026-09-01  二つ目の実行ファイルを起こさない（NetVision に倣う）

利用者に「NetVision だと動くのに、なぜこっちは動かないのか」と問われて、
**初めて NetVision を見た。**見ずに WASM を提案していた。

NetVision の `backend/app/services/llm_inproc.py` に、答えがそのまま書いてある。

> サーバーを別に立てる形（Ollama や llama.cpp の server）は、
> 実行ファイルが1つ増えるため、そこで止まる。

| | NetVision | AdaptiveAIStudio（これまで） |
|---|---|---|
| 土台 | `python.exe`（アプリ自身） | `node.exe`（`.bin` でも可） |
| モデルを読むもの | `lib/` の `llama-cpp-python`（.dll） | **`llama-server.exe` を別に起こす** |
| 増える実行ファイル | なし | **1つ増える** |

だから `runtime.kind: "inproc"` を足した（`src/runtime/inproc.ts`）。
`node-llama-cpp` は中身が `.dll` と `.node` だけで、`.exe` は0個（実測）。

上の層は OpenAI 互換の口しか見ないので、**その口を自分の中に立てる**
（127.0.0.1 のみ。外へ出る口は増えない）。上の層は一行も変えていない。

## 2026-09-01  塊ごとに toString() しない

**決めたこと**

子プロセスや流れから届いた塊を、その場で文字に直さない。
またぐ分を持ち越すもの（`StringDecoder` / `TextDecoder({ stream: true })`）を通す。

**なぜ**

日本語は1文字3バイト。塊の切れ目が文字の途中に来ると、そこで化ける。
**長い返事のときだけ**起きるので、短い試しでは気づけない。
MCP の口（`src/mcp/client.ts`）が塊ごとに `toString()` していた。

検査は、1バイトずつ返す相手（`test/fixtures/dribble-mcp.mjs`）を置いて
必ず起きるようにした。直す前に戻して、落ちることを確かめてある。

同じ書き方が9か所あった（画面の検査出力、shell の結果、git の出力、
llama-server の記録、inproc が受け取る本文まで）。`src/core/text.ts` の
`chunkReader()` / `lineReader()` に寄せた。

**読み手は流れごとに作る。**stdout と stderr で一つを使い回すと、
持ち越しが相手のものと混ざって両方化ける。使い回すと壊れることも検査に置いた。

行も同じ。塊の切れ目は行の切れ目でもないので、塊ごとに `split('\n')` すると
**一行が二行に割れて**流れに出る（llama-server の記録で起きていた）。

**ついでに決めたこと**

- 改行を一度も出さない相手のために、溜め込みに上限を置く（8MB）。
  上限を置かないと、壊れた相手一つでこちらが落ちる。
- 立ち上げ直すときは、前の失敗の理由を捨てる。残すと、直った後も
  済んだ失敗を「なぜ無いのか」として言い続ける。

## 2026-09-01  ファイルは UTF-8 と決めつけない

**決めたこと**

当てずっぽうで CP932 にはしない。UTF-8 として通るものは UTF-8。

## 2026-09-02  読む前に、読めるか・載るかを見る

**決めたこと**

**決めたこと**

小さいモデルは作業の途中で平気で手を止める。
「では次に src/a.ts を書き換えます」と言って、そこで返してくる。

自律で回し続けられなかったのは、毎回ここで降りていたから。
ローカルの小さいモデルほど、この降り方をする。

道具を使った後で止まったときだけ押し戻す。

**動かないものは、動かないと言う**

押し戻しは只ではない（一往復ぶん余計に考えさせる）ので、回数を決めて打ち切る。
押し戻したことは画面に出す。黙って往復が増えると、遅いだけに見える。

**試験の側**

偽モデルにも合図を書かせる。書かせないと、**決まりに従わないモデル**だけを
相手にした試験になり、押し戻しの側しか見ないことになる。

## 2026-09-03  文脈の窓は、こちらで決めて刈る

**決めたこと**

送る前に、履歴を窓に収める（`src/agent/window.ts`）。
**元は変えない。**送る分だけを作る。

**なぜ**

履歴を**一度も刈っていなかった**。外の大きなモデルなら入るので済んでいた。
ローカルは違う。会社の機械に載る大きさだと窓は 8192 で、
ファイルを2つ3つ読んだ時点で溢れる。

溢れたときが、いちばん悪い。ライブラリは**古い方から黙って落とす**
（contextShift）。落ちるのは、いちばん古いもの＝**最初の依頼**。
何をしていたのかを忘れたまま道具だけを呼び続ける。
止まらないので気づけない。**自律で回すほど、確実にここへ来る。**

**順番**

1. 最初の依頼は落とさない（何をしているのかが消える）
2. 直近のやりとりは落とさない（いま何をしているかが消える）
3. 減らすのは、まず**古い道具の結果**（かさの大半はこれ）
4. それでも溢れるなら、古い往復を丸ごと落とす
5. まだ溢れるなら、直近も縮める。**落とすより縮める**
   （落とすと往復の筋が消えるが、縮めれば何をしたかは残る）

**切り離さない**

道具を呼んだ assistant と、その結果の tool は離せない。片方だけ落とすと、
OpenAI 互換の口が形の違うものを受け取って落ちる。往復のかたまりで扱う。

**窓の大きさは、実際に立てたものを使う**

`runtime.contextSize` / `desiredContext`。見誤るなら**狭い側に倒す**
（広いと思って溢れさせると、黙って落ちる方に回る）。

## 2026-09-03  歩幅をモデルに合わせる（落ちたら小さく割り直す）

**決めたこと**

一度で通らなかった依頼は、**同じ大きさで挑み直さない。**
歩ける大きさの段に割って、一段ずつ進む。割り方の細かさは、
**そのモデルが実際にこなせた歩幅**から決める。

- `src/agent/stride.ts` 歩幅を測って覚える
- `src/core/goals.ts` 段取り。落ちた段を割り直す
- `src/agent/decompose.ts` 割る（モデルに割らせるが、信用しない）

**なぜ**

依頼の大きさは**人が決めたまま**モデルへ渡していた。外の大きなモデルなら
通る。ローカルは通らない。

    「src を直して」          4B には大きすぎる。読んだだけで力尽きる
    「src/a.ts の型を直して」 これなら通る

そして**落ちたときに同じ大きさで挑み直していた**。通らなかったものを
もう一度そのまま渡しても通らない。三回やって諦める、を繰り返すだけだった。
分解する仕組み（PM）はあるが一度きりで、**落ちても細かくならない。**

ここが、この道具の名前どおりの部分。**合わせるのは、モデルではなく歩幅。**

**測り方**

通ったら少しずつ広げ、落ちたらすぐ狭める。広げるのは三回続けて通ってから、
狭めるのは一度で。**対称にしない**（落ちる方が高くつく。やり直しの時間も、
壊れたものを戻す手間も）。測る前の一回目は、窓の広さから見当をつける
（外れても、一回落ちれば狭まる。**外れる前提で置く**）。

**割り直しは一度だけ**

割った先がまた駄目なら、それは大きすぎるのではなく**そもそも出来ない**
（前提が足りない、道具が無い、読み違えている）。さらに割ると意味の無い
断片が増えるだけ。そこは手が付かないものとして脇へ置き、**次の段へ進む**。
一段で全部を止めない。止めると、独立して進められる残りまで道連れになる。

**一段の合否は、言葉ではなく道具が動いた跡で見る**

作っている途中で見つけた。「では、このあと直します」と言っただけの回を
**済んだと数えていた**。何もしていない段取りが、順調に進んだ顔で終わる。
段は「やること」を渡しているので、道具が動いていなければ済みにしない。

**割れないことは、進めない理由にならない**

小さいモデルは平気で壊れたものを返す。番号だけ、前置き、丸ごと作文。
形を整えさせるより**こちらで拾う**（守らせようとするほど中身が薄くなる）。
拾えないなら割らずに、これまでどおり丸ごと渡す道へ落ちる。

**見えること**

一段ずつ進むので、見えないと「止まっている」のか「一段ずつ進んでいる」
のかが区別できない。横の板に段と進み具合を出す。

**終わり方（作った直後に見つけた穴）**

段が尽きたあと、**手が付かなかった段があっても丸ごと投げ直す道へ落ちて**
いた。割っても通らなかったものを、まとめて渡せば通る道理がない。
そこで諦め、**何が出来て何が出来なかったかを言う**（黙って消すと、
頼んだことが消えたようにしか見えない）。
全部通ったなら、やり残しの控えも一緒に片づける。

**通った段の次は、待たずに次へ**

一段ごとに見回り（30秒）を待つと、10段の段取りで**待ち時間だけ5分**になる。
通った段の次は、そのまま次へ進む。**落ちた段のあとだけ間を置く**
（詰めて回すと、落ちているときに同じところを高速で叩き続ける）。

人の依頼が先。作業中・支度中・順番待ちがあるなら始めない（次の見回りが拾う）。
前の回の後始末が終わってから始める。詰めすぎると、busy を下ろし切る前に
次が立ち上がって、自分で自分を弾く（実際にそうなり、二段目で止まった）。

## 2026-09-04  コードを見つけられるようにする（索引と、言葉での当て方）
