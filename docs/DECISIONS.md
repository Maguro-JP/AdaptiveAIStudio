## 2026-09-01  検証は社用PCでも続ける

**決めたこと**

| 場所 | どうする |
|---|---|
| 自宅 | インストーラで綺麗に入る。更新も、不要ファイルの削除も自動 |
| 社用PC | インストールせずに検証を続けられる。git 不可・Node 不可・管理者権限なし |
| CI | 節約する。枠を使い切ると何も確かめられなくなる |

**「Node 不可」の意味**

インストールが不可、という意味。フォルダに `node.exe` を置いて動かすのは
インストールではない。`installer\bootstrap.cmd` とportableはこのために在る。

**やらないこと**

- USB を社用PCに挿す提案。多くの会社で規程違反であり、塞がれている。
  持ち込む方法ではなく、**その場で取ってくる**方法を用意する。
- 「社用PCを諦めては」と言い出すこと。実際に言い出して怒られた。

## 2026-09-01  C: 直下を汚さない

`C:\AAS` や `C:\ai` を作らない。消し忘れて残る場所であり、汚してよい場所ではない。
Windows が用意している置き場を使う。

| | 置き場所 |
|---|---|
| 利用者ごと（管理者権限なし） | `%LOCALAPPDATA%\Programs\AdaptiveAIStudio\` |
| 全体（インストーラ） | `%ProgramFiles%\AdaptiveAIStudio\` |
| portable | 置いたフォルダの中だけ |

利用者名が全角でも止めない。困るのはモデルだけなので、モデルだけ
`%ProgramData%\AdaptiveAIStudio\models` へ逃がす（`src/core/home.ts` の `asciiModelsDir`）。

## 2026-09-01  バッチは CP932 で置く（BOM は付けない）

社用PCの実行結果で分かった。cmd.exe はバッチを console の文字集合で読むので、
UTF-8 で置くと行が壊れて断片が実行される。BOM は 1 行目を壊し、`@echo off`
まで効かなくする。`chcp 65001` では直らない（読むのは実行前だから）。

記録は UTF-8 のままにする。`.gitattributes` の `working-tree-encoding=CP932`
で、取り出すときだけ変える。GitHub の「Download ZIP」にも効く（確認済み）。

## 2026-09-01  社用PCから github.com へは繋がらない

curl が 443 で timeout（21秒 × 4回）。ブラウザでは claude.ai が見えているので、
**串（プロキシ）をブラウザだけが知っている**可能性がある。
`netsh winhttp show proxy` で調べ、`set HTTPS_PROXY=...` を渡す道を用意した。

## 2026-09-01  社用PCでは、手で二つ落とす

デスクトップアプリ（中身はブラウザ）は Windows のシステムのプロキシ設定を
使うので繋がる。`curl` は使わないので繋がらない。**curl を通さない道にする。**

1. GitHub の「Download ZIP」を落として、好きな場所に展開する
2. `https://nodejs.org/dist/v24.18.0/win-x64/node.exe` を落として、
   `start.cmd` の隣に `node\node.exe` として置く
3. `start.cmd` を叩く

インストールではない。管理者権限も要らない。フォルダごと消せば何も残らない。
`start.cmd` は最初から `%~dp0node\node.exe` を見るので、これで見つかる。

## 2026-09-01  portable は Releases に常時置く

「同梱してあります」と言いながら、Node の入った現物をどこにも置いていなかった。
落とせないものを、あるかのように言わない。

  https://github.com/Maguro-JP/AdaptiveAIStudio/releases/tag/portable

`main` を更新して配布物を回すたび、この印（portable）の中身が差し替わる。

代わりに `node\` フォルダを置き、README.txt に落とし先だけ書いてある。

## 2026-09-01  Actions は、断ってから回す

**利用者に聞かずに回さない。**手で回す（workflow_dispatch）のも同じ。
実際に、断らずに2回回した（合計2分・Linux）。量の問題ではなく、
「節約して」と言われている枠を、勝手に使ったことが問題。

回す前に、必ずこう言う。

  ・何のために回すのか
  ・どの機械で、何分くらいか（Windows は2倍で数えられる）
  ・回さずに済む道があるか

**回さずに済む道が先。**portable は `npm run bundle -- --node-here` で
手元でも作れる（網も CI も要らない）。Actions が要るのは、
利用者の手元に Node が無いときと、`setup.exe` を組むときだけ。

## 2026-09-01  名前は英語。無理に日本語にしない

同じものを四つの名前で呼んでいた（WindowsBundle / 配布物 / portable /
portable）。利用者が「言ってることがめちゃくちゃ」になるのは当然だった。

| 言葉 | 何を指すか |
|---|---|
| `npm run bundle` | **コマンド**。portableのフォルダを作る |
| portable | **もの**。アプリ + node.exe が入ったフォルダ |
| Releases | **置き場**。GitHub のダウンロード置き場 |
| Actions | **実行環境**。GitHub 上でコマンドを走らせる場所 |
| 検査 | `npm test` のこと。それを Actions で走らせるのが CI |

以後 `portable` とだけ呼ぶ。**無理に日本語に訳さない。**
CLAUDE.md に「名前は普通のプログラムの作法（英語）」と書いた本人が、
portable を「portable」に変えて不快にさせた。訳語を作らない。

## 2026-09-01  根を散らかさない

利用者に「なんで GitHub こんな汚くなってるの」と言われた。

- `node\` を消した。portable に node.exe が入っているので要らない。
  そもそも一時しのぎで足したもので、置きっぱなしにしていた。
- `start-ui.cmd` / `start-ui.sh` を消した。中身は `start.cmd ui` を
  呼ぶだけの4行。入口は一つでよい。

根に置いてよいのは、入口（`start.cmd` / `start.sh`）と、
道具が読む決まりもの（package.json・tsconfig.json・.gitattributes 等）と、
人が最初に読むもの（README.md・CLAUDE.md・VERSION）だけ。
