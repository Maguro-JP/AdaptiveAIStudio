## 2026-09-01  検証は社用PCでも続ける

**決めたこと**

| 場所 | どうする |

| 自宅 | インストーラで綺麗に入る。更新も、不要ファイルの削除も自動 |

  持ち込む方法ではなく、**その場で取ってくる**方法を用意する。

## 2026-09-01  二つ目の実行ファイルを起こさない（NetVision に倣う）

利用者に「NetVision だと動くのに、なぜこっちは動かないのか」と問われて、
**初めて NetVision を見た。**見ずに WASM を提案していた。

NetVision の `backend/app/services/llm_inproc.py` に、答えがそのまま書いてある。

> サーバーを別に立てる形（Ollama や llama.cpp の server）は、
> 実行ファイルが1つ増えるため、そこで止まる。

| | NetVision | AdaptiveAIStudio（これまで） |
|---|---|---|
| 土台 | `python.exe`（アプリ自身） | `node.exe`（`.bin` でも可） |
| モデルを読むもの | `lib/` の `llama-cpp-python`（.dll） | **`llama-server.exe` を別に起こす** |
| 増える実行ファイル | なし | **1つ増える** |

だから `runtime.kind: "inproc"` を足した（`src/runtime/inproc.ts`）。
`node-llama-cpp` は中身が `.dll` と `.node` だけで、`.exe` は0個（実測）。

上の層は OpenAI 互換の口しか見ないので、**その口を自分の中に立てる**
（127.0.0.1 のみ。外へ出る口は増えない）。上の層は一行も変えていない。

### 言い方を間違えた

「ライブラリを足すと環境依存になる」と言ったが、逆。
**足りない環境に合わせて入れるのは、環境に対応したというだけ。**
`node.exe` を同梱しているのと同じ話で、破っているものは無い。

### Node にこだわる理由は無い

私が最初にそう決めただけで、要件ではない。ただし今回の壁は Node ではなく、
「二つ目の実行ファイルを起こす」という作りだった。言語を替える必要は無かった。

### 全機械むけの binary を入れない

`npm install node-llama-cpp` をそのまま叩くと 1.1GB になる。

- CUDA 版・mac 版・arm 版まで来る（**`--os` / `--cpu` は効かない。試した**）
  → `--omit=optional` で持ってこない。配る相手の分だけ名指しで入れる
  （Linux で組むので `--force` が要る）
- postinstall が llama.cpp のソースを取ってきて手元で組む（+292MB。
  Linux むけなので配る相手には要らない）→ `--ignore-scripts`

結果、配布物は 42MB（node 抜き・実測）。`.exe` は0個。

**インストーラ側にも同じものを入れる。**抜かすと「setup.exe だけ
モデルを中で読めない」という食い違いになる。アンインストールは
`RMDir /r "$INSTDIR\app"` が node_modules ごと消すので、そのままでよい。

## 2026-09-01  塊ごとに toString() しない

**決めたこと**

子プロセスや流れから届いた塊を、その場で文字に直さない。
またぐ分を持ち越すもの（`StringDecoder` / `TextDecoder({ stream: true })`）を通す。

**なぜ**

日本語は1文字3バイト。塊の切れ目が文字の途中に来ると、そこで化ける。
**長い返事のときだけ**起きるので、短い試しでは気づけない。
MCP の口（`src/mcp/client.ts`）が塊ごとに `toString()` していた。

検査は、1バイトずつ返す相手（`test/fixtures/dribble-mcp.mjs`）を置いて
必ず起きるようにした。直す前に戻して、落ちることを確かめてある。

同じ書き方が9か所あった（画面の検査出力、shell の結果、git の出力、
llama-server の記録、inproc が受け取る本文まで）。`src/core/text.ts` の
`chunkReader()` / `lineReader()` に寄せた。

**読み手は流れごとに作る。**stdout と stderr で一つを使い回すと、
持ち越しが相手のものと混ざって両方化ける。使い回すと壊れることも検査に置いた。

行も同じ。塊の切れ目は行の切れ目でもないので、塊ごとに `split('\n')` すると
**一行が二行に割れて**流れに出る（llama-server の記録で起きていた）。

**ついでに決めたこと**

- 改行を一度も出さない相手のために、溜め込みに上限を置く（8MB）。
  上限を置かないと、壊れた相手一つでこちらが落ちる。
- 立ち上げ直すときは、前の失敗の理由を捨てる。残すと、直った後も
  済んだ失敗を「なぜ無いのか」として言い続ける。

**なぜ**

製品の形では起動時の場所が `app\` で、そこに設定は無い。画面から保存すると `app\` に
書いていた。インストール先（Program Files）は書けず、portable でも更新で `app\` ごと消える。
さらに設定が無いと既定が Ollama だったので、GGUF を置き場に入れても
「Provider が起動しているか確認してください」で止まる。**「動く」と言って動かなかった一つ。**
二つ目の実行ファイルの要らない道を既定にする、と決めてあったのに、既定がそうなっていなかった。

**確かめていないこと**

Windows の実機で、インストール後に画面から保存して `%ProgramData%\AdaptiveAIStudio\aas.config.json`
に書けること（icacls で Users に変更権限を付けてあるが、実測はまだ）。

## 2026-09-03  打てない一手を出さない

**決めたこと**

案内に書く一手は、**その場所で打てるものだけ**にする。配布物（portable・インストール）には
npm が無いので、`npm run ui` や `npm run models -- --get` と書いたら打てない。
入口（`AdaptiveAIStudio.cmd`）が package.json をそのまま読んで同じ仕事を動かすので、
呼び方だけを差し替える（`doctor.ts` の `how()`）。

並べる側（`doctor-view.ts`）に環境を判断させない。**呼ぶ側が決めて渡す**（`HowToStart`）。
置き場を渡すのと同じ考え方。

**なぜ**

配布物の doctor の締めが「画面（npm run ui）は、モデルが無くても開けます」だった。
モデルが無い人がいちばん見る一行が、打てない一手だった。同じ型で、モデルの取り方、
llama-server の用意、binary が無いときの案内も打てなかった。

**あわせて**

`guessVersion` の試験に `sourceOnly` を付けた。git の作業コピーでしか確かめられないのに、
配布物の中で走らせると落ちていた（走らせる場所で結果が変わる試験を書かない、の実例）。
配布物の中でも 1172 件が通ることを見た。
