# アイデア（拡張機能）

パネル「アイデア」は、今の作業の語と、外の世界の仕組みを掛け合わせて、アイデアの札を出します。
公開のリポジトリ [IDEAMAN](https://github.com/Maguro-JP/IDEAMAN) の考え方とデータを、この本体に移して同梱したものです。

考えを出し合い、可能性を探り、考えを育てる場所として使います。思いつきを 1 行で置くと、広げた札が返り、
育てたい札を選ぶと、その札を種に次の札が出ます。育てた流れは 1 本の筋として残り、あとで開き直せます。

札は、推論で作りません。文の型に、材料・側面・操作・試し方を当てはめて作ります。
だから、モデルもネットワークも要りません。開いただけで札が並びます。

## 使い方

1. 左上の ⊞（表示）で「アイデア」にチェックを入れます。パネルが出て、札が 4 枚並びます。

### 思いつきを置いて、育てる

1. いちばん上の欄に、思いつきを 1 行で書いて「広げる」（または Enter）。その思いつきの語を材料に広げた札が 4 枚返ります。
   思いつきは、筋の頭として残ります
2. 育てたい札の「育てる」を押します。その札が筋に足され、その札を種にした次の札が 3 枚出ます。
   繰り返すと、育てた順に 1 本の筋として並びます
3. 「筋を依頼に入れる」で、思いつきと育てた札を順に、チャットの入力欄に入れます
4. 「筋を閉じる」で、元の札に戻ります。筋は残っていて、「筋の一覧」の「開く」で開き直すと、続きの札が出ます。立ち上げ直しても残っています

思いつきが 1 語（「棚卸し」）なら、その語が材料になります。語を採れない思いつき（ひらがなだけ）は、今のテーマの語で広げます。

### 並んだ札を使う

2. 上の「テーマの語」が、札の材料です。今の作業場のフォルダの名前と、見ている会話の直近の依頼から自動で採ります。
   - 語を足す: 欄に語を入れて「足す」（または Enter）。その語の札がすぐ出ます
   - 語を外す: 語の × を押します。その語の札は出なくなります。すぐ下の「取り消す」で、語と前の札が戻ります。
     あとから戻すときは、「「語」を戻す」を押します
3. 札ごとに、1 回押すだけのボタンが 4 つあります。
   - もっと: その札の主題（材料・概念・側面）を引き継いだ、別の型の札を 1 枚、札の下に伸ばします
   - なぜ: 掛け合わせた語と、元の仕組みの文と、その出典（ウィキペディアの記事の URL とライセンス）を出します
   - ☆ 残す: 札を残します。その札の語の重みが上がり、次からその語が出やすくなります。もう一度押すと、やめて重みを戻します
   - 依頼に入れる: チャットの入力欄に、札の文を入れます
4. 札を 2 枚選んで（左上のチェック）「組み合わせる」を押すと、1 枚目の主題に 2 枚目の主題をぶつけた札が、いちばん上に出ます。
5. 「別の札を出す」で出し直します。「前の札に戻す」で、出し直す前の札に戻れます（直近の 10 回分）。
6. 「残した札」で、残した札の一覧を見ます。立ち上げ直しても残っています。

「モデルで磨く」にチェックが入っていて、手元のモデルを読んであるときだけ、札の文をモデルが整えます。
整えた札には「元の文」のボタンが出て、掛け合わせたままの文に戻せます。モデルがいちばん試す値打ちがあると見た 1 枚に、しるしが付きます。
モデルが無い・まだ読んでいない・作業中のときは、何もしません（札はそのまま使えます）。磨くためにモデルを読みには行きません。

切るときは、⚙（設定）→ 拡張機能 で「アイデア」のチェックを外します（[拡張機能](EXTENSIONS.md)）。

## 仕組み

| 部品 | すること |
|---|---|
| `src/extensions/ideas/data/` | 語のプール・文の型・外の世界の仕組みの文（JSON） |
| `combinator.ts` | 型に語を当てはめて、札の種を 1 つ作る。概念を 2 つ引くときは、分野の重なりが少ない（遠い）組を選ぶ |
| `themes.ts` | テーマの語を、作業場の名前と直近の依頼から採る。文は語として受けない |
| `service.ts` | 札を出す・連鎖の次を出す・2 枚から出す・残す。語の重みを動かす |
| `store.ts` | 蔵（AAS_HOME のデータの下の、拡張機能のフォルダの JSON 1 本） |
| `polish.ts` | 手元のモデルに頼む文を作り、返事を読む（決めた形の行だけを受ける） |
| `rng.ts` | 種を渡せる乱数。同じ種なら同じ札 |

- 文の型は 2 種類です。提案（「{材料}の{側面}を{操作}。まず{試し方}。」）と、問い（「{材料}の{側面}は、なぜ今の形なのか。」）
- 仕組みの札（`mechanism_transfer`）は、外の世界の仕組みの 1 文を、材料の側面に移します。
  例: 「引き出したベルトを任意の位置で停止させることで自動的にロックする（シートベルト）。通知の失敗したときの挙動で同じことをするなら、何が要るか。」
  材料が在るときは、1 度に出す札の中に 1 枚は入れます
- 語の形を混ぜません。疑問節の側面（「誰が決めるか」）は問いの型にだけ入れ、「{側面}を{操作}」の操作は、自分の目的語を持たない動詞だけにします
- 材料と同じ語は、概念として引きません（「通知と通知は…」を出さない）
- 同じ型の札は並べません。種を渡さないときは、前に出した札と同じ組み合わせを引き直します
- 残すと、その札の語（試し方を除く）の重みに 1.25 を掛けます。やめると 1.25 で割って戻します。重みは 0.2 から 5 の間です
- 蔵に覚えるのは、出した札 200 枚（古いものから落とす）、残した札 500 枚（上限では、足すのを断る）、筋 100 本（古いものから落とす。1 本に札 50 枚まで）、足した語・外した語それぞれ 100 個までです
- 種を渡すと、同じ蔵の中身（重み・テーマの語）なら同じ札が出ます（`POST /api/ideas/receive` の `seed`）

## API

口の名前は、後から MCP で繋げるように、IDEAMAN のツールの名前に寄せてあります。MCP のサーバーは、まだ作っていません。
拡張機能を切ってある間は、どれも 404 を返します。スマホの口（LAN）には出していません。

| 口 | すること | IDEAMAN のツール |
|---|---|---|
| `POST /api/ideas/receive` | 札を出す（`count`・`seed`・`focus`） | `ideaman_receive_idea` |
| `GET /api/ideas/browse` | 残した札 | `browse_ideas` |
| `POST /api/ideas/follow_chain` | 連鎖の次を出す（`id`） | `follow_chain` |
| `POST /api/ideas/rate` | 残す・やめる（`id`、`value` は 1 か 0） | `rate_idea` |
| `POST /api/ideas/register_theme` | 語を足す（`term`） | `register_theme` |
| `GET /api/ideas/list_themes` | 今の語と、外した語 | `list_themes` |
| `GET /api/ideas/stock_status` | 同梱のデータの数と、蔵の数 | `stock_status` |
| `POST /api/ideas/plant` | 思いつきを 1 行で置いて、広げた札を受け取る（`text`・`seed`） | （無い。この本体で足した） |
| `POST /api/ideas/grow` | 札を筋に足して、次の札を受け取る（`thread`・`id`。`id` を省くと、筋を開き直すだけ） | （無い。この本体で足した） |
| `GET /api/ideas/threads` | 筋の一覧 | （無い。この本体で足した） |
| `POST /api/ideas/combine` | 2 枚から出す（`a`・`b`） | （無い。この本体で足した） |
| `POST /api/ideas/remove_theme`・`restore_theme` | 語を外す・戻す | （無い。この本体で足した） |
| `POST /api/ideas/polish`・`unpolish`・`polish_enabled` | 手元のモデルで磨く・元に戻す・入り切り | （無い。IDEAMAN では仕上げの段） |

## IDEAMAN から移したもの・移していないもの

移したもの:

- データ 3 本（`ideaman/data/` の `lexicon.yaml`・`templates.yaml`・`mechanisms.yaml`）。中身は変えず、JSON に直しました（この本体は YAML を読む部品を持ちません）。
  語 169、型 18、仕組みの文 128（側面が付いていて札に引かれるのは 57）
- 抽選（IDEAMAN の combinator）: 型の選び方、遠い組の選び方、語の形の区別、材料を先に決めて重なりを避ける、連鎖で主題の語を引き継ぐ、署名（同じ組み合わせかどうか）
- 材料の語の確かめ（IDEAMAN の蔵の `clean_material`）
- 重みの下限と上限、試し方の語を評価に数えないこと
- 仕上げの考え方（IDEAMAN の refiner）: 材料の語を残す、長くなりすぎた返事は受けない、失敗しても元の文を出す

移していないもの:

- 思考のリズム（連想と放浪の切り替え、休眠、火花）。この本体では、連鎖を伸ばすかどうかを「もっと」で利用者が決めます
- 気分（moods）による語調の引っぱり。データは同梱していますが、使っていません
- 在庫を先に作っておく段、Discord の Bot、ウィキペディアから仕組みの文を採る段（harvest）、SQLite の蔵
- 重複に戻ってきたときの弱い加点、平均の評価からの重みの計算（この本体は、残す・やめるの 2 つだけ）

思いつきを置く・育てる・筋と、「組み合わせる」は、この本体で足しました（IDEAMAN には有りません）。
筋は、IDEAMAN の連鎖（札から次の札へ）を、利用者が選んで進める形にしたものです。

## ライセンス

- 仕組みの文（`mechanisms.json` の `how`）は、日本語版ウィキペディアの記事の文で、CC BY-SA 4.0 です。
  出典の記事の URL を 1 件ずつ持ち、札の「なぜ」に出します。出典の記事の一覧と、変えた所は `src/extensions/ideas/data/NOTICE.md` に在ります
- 語のプールと文の型は、IDEAMAN のリポジトリのものです。IDEAMAN のリポジトリにライセンスのファイルは見当たりませんでした（2026-11-28 に見た）。
  同じ持ち主の公開のリポジトリから移していますが、ライセンスの決めは利用者に委ねます
- 配る形（bundle・setup.exe）には、データと `NOTICE.md` がそのまま入ります（`app/src/extensions/ideas/data/`）。`README.txt` にも 1 行書いてあります

- `test/ideas.test.ts`: データ・抽選・テーマの語・残す・もっと・組み合わせる・なぜ・蔵・磨きの返事・思いつきを置く・育てる・筋
- `test/extensions.test.ts`: 入り切り・切ると API が 404・入れ直すとデータが戻る・片づけ


## 確かめていないこと

- 本物のモデルで磨いた文の出来。頼む文と、返事の読み方は試験で見ていますが、本物のモデルに通した結果は見ていません
- Windows の実機と、setup.exe で入れた形。CI の `ideas` は回していません
- 札の中身が役に立つかどうか。出る・押せる・残るは見ていますが、思いつきとしての値打ちは測っていません
- 自動で採る語は、カタカナ・漢字・英字の連なりを拾うだけです。「設定画面」のように、切れ目の無い漢字は 1 語になります
