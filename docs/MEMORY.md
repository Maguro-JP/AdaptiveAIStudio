# 記憶

起動のたびに何も覚えていないなら、それは道具であって住人ではない。

決めたこと、試して駄目だったこと、調べて分かったこと、利用者の好み。
これが残らない限り、同じ失敗を無限に繰り返す。
「AIが動く場所」を名乗る以上、ここが空なのは構造的な欠落になる。

## 覚える五種類

| 種類 | 何を | 寿命 |
|---|---|---|
| `decision` | 決めたこと。方針・設計判断 | 刈らない |
| `preference` | 利用者の好み・流儀 | 刈らない |
| `attempt` | 試したこと（うまくいった/駄目だった） | 確度と新しさで残る |
| `fact` | 調べて分かったこと | 同上 |
| `incident` | 起きたこと。障害・事故 | 同上 |

決めたことと好みは刈らない。それが土台だから。

## 外せない三点

### 1. 確度は回数で上がる

一度見たことは仮説、何度も確かめられたことは事実に近い。
同じことを覚え直したら、上書きではなく確認回数を増やす。

思い出すときも確認回数が効く。一度きりの思いつきより、
何度も確かめられたことが先に出る。渡すときには確度も添える。

```
これまでに分かっていること:
  [分かったこと/確か] 停滞で打ち切ると、遅いモデルでも通る
  [試したこと/一度だけ] 総時間で打ち切る（失敗した）
      遅いモデルが必ず殺される
```

「一度だけ」と書いてあるものを、事実として扱わせないため。

### 2. 決め直しは消さずに繋ぐ

古い決定を消すと「なぜ変えたのか」が失われる。
新しい決定から古い決定へ矢印を張り、履歴として残す。
思い出す対象からは外れるが、辿れば出てくる。

役職を消さないのと同じ考え方。

### 3. 矛盾は黙って飲み込まない

同じ話題で前と違うことを決めたなら、それは報告に値する出来事。

```
> /remember 決定: 既定は auto
  前にこう決めています: 既定は autoEdit
    決め直すなら、そう言ってください（m12）
```

食い違いかどうかの最終判断は人がする。ここは見つけて出すまで。

## 同じ失敗を繰り返さない

記憶の値打ちは、貯めることではなく始める前に思い出すことにある。

`/plan` は分解の前に、依頼に関係する記憶と、前に駄目だった手を引き出して
PM に渡す。通常の依頼でも同じものが添えられる。
これを渡さないから、同じ手を何度もやり直すことになる。

同じ依頼が二度目なら、そう言う。

```
  この依頼は 2 回目です。前回の結果も記憶にあります。
```

## 作りの方針

埋め込みも外部データベースも使わない。
語の重なりと新しさと確認回数で十分に効く。
動く条件を増やさないことも、止まらないための設計のうち。

保存は JSONL。1行壊れても記憶全体を失わない。

話題が重ならない記憶は思い出さない。全部渡すのは、雑音を渡すのと同じ。

## コマンド

| コマンド | 何をするか |
|---|---|
| `/memory` | 最近覚えたこと |
| `/memory <語>` | その語に関係する記憶（決め直し済みも含む） |
| `/remember <文>` | 好みとして覚える |
| `/remember 決定: <文>` | 方針として覚える。矛盾があればその場で言う |
