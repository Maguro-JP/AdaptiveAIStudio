# 置き場に何が入るか、何が守っているか

持ち出されたら何が読まれるのかを、先に書いておく。
守り方を決めるのは利用者なので、こちらは事実だけ並べる。

別のプロジェクトで使った形を元にしている。結論は借りず、同じ問いをこの保存先について立て直した。

## いまの状態

置き場は `AAS_HOME`（portable なら `AdaptiveAIStudio\data\`、
入れた版なら `%ProgramData%\AdaptiveAIStudio\`）。中身はこう。

| 何 | 入っているもの | 重み |
|---|---|---|
| `conversations/` | やりとりの全文。読ませたファイルの中身も、そのまま入る | 作業場のコードと同じ |
| `undo/` | 書き換える前のファイルの中身（戻すために控えている） | 同上 |
| `attachments/` | 渡したファイルの実体 | 渡したもの次第 |
| `memory.jsonl` | 覚えたこと・嫌がられたこと | 書いた本人の言い回しが残る |
| `audit.jsonl` | いつ何をしたか。中身は残さない（要約と、外へ出た先だけ） | 低い |
| `.env` | 合言葉そのもの（`GITHUB_TOKEN` など） | いちばん重い |
| `logs/` | 動かしたときの記録 | 低い |
| `index/` | 作業場の索引（ファイルの頭と注釈） | 作業場のコードと同じ |
| `metrics.json` ほか | 実測・段取り・配置などの控え | 低い |

使ったものから順に出来る（`.env` は GitHub に繋いだときだけ）。
上の表は実際に一往復させて中を見て書いた。会話と undo にファイルの中身が
そのまま入ること、`audit.jsonl` には入らないことは、目で確かめてある。

つまり前提は、「置き場を、作業場のコードと同じ扱いで守る」。
持ち出されたら、コードを持ち出されたのとほぼ同じことになる。

## いま効いている守り

| 何が | どこまで |
|---|---|
| 画面は `127.0.0.1` だけで待ち受ける | 同じネットワークの他の人からは開けない。同じ機械の他の利用者は開ける |
| `.env` は 600 で置く | 同じ機械の他の利用者からは読めない（Windows では権限の考え方が違い、ほぼ効かない） |
| 外へ出るものは検問所を通る | 鍵・トークン・資格情報は止める。行き先は記録する（中身は残さない） |
| ログインの仕組み | 無い。だから `127.0.0.1` にしか待ち受けない |

## 足すとしたら

どれを選ぶかは利用者が決める。こちらから前提を変えない。

### 1. OS のディスク暗号化に任せる（いちばん安い）

Windows なら BitLocker。配布された端末なら、たいてい既に掛かっている。

- 良いところ: こちらの実装はゼロ。鍵の管理も情シスの仕組みに乗る
- 効かないところ: 端末が動いている状態でファイルを取られると効かない
- 向くのは: 1人が自分の端末で使う、いまの使い方

まず「この端末に既に掛かっているか」を確かめる。掛かっているなら、
こちら側で暗号化を足しても、増える守りは限られる。

### 2. 置き場そのものを暗号化する

- 良いところ: フォルダを持ち出されても読めない
- 効かないところ: 鍵をどこに置くかが新しい問題になる。隣に置けば意味が無く、
  起動のたびに打つなら、それはログインを作るのと同じ手間
- 向くのは: 端末を共有している、または持ち出す使い方

### 3. 会話と undo を短く保つ

いま溜め続ける作り（会話は残り、undo は 30 件まで）。
古いものを自動で消せば、持ち出されたときに読まれる量が減る。

画面で消した会話は、立ち上げ直すまで会話のフォルダの `trash/` に残る（押し間違えを戻すため）。
立ち上げたときに `trash/` ごと消す。消した後もしばらくはディスクに在る、ということは知っておく。

- 良いところ: 実装が小さい。鍵の置き場所の問題が出ない
- 効かないところ: 消したものは戻せない。「前に言ったこと」を引けなくなる

## 「これでしか開けない」は作れるか

作れる。ただし鍵の置き場所で決まる。

| 置き方 | 守れる | 守れない |
|---|---|---|
| 置き場の隣に鍵 | 1ファイルだけ抜かれたとき | フォルダごとコピーされたら開ける |
| 別のドライブに鍵 | 置き場だけ持ち出されたとき | 端末ごと取られたら両方ある |
| OS の資格情報ストア | 他の利用者からは開けない | その端末のその利用者として動かれたら開ける |
| 起動のたびに人が打つ | 上の全部 | 毎回の手間。忘れると誰も開けない |

「これでしか開けない」と言えるのは、鍵がこちらの外（人の頭か OS の金庫）に
ある場合だけ。鍵をファイルとして一緒に置くなら、正しくは
「これと、その鍵を持っている人なら開ける」になる。

## 決めていないこと

上の 1〜3 は、まだどれも選んでいない。いまは「置き場をコードと同じ扱いで
守る」という前提のまま動いている。選んだら `DECISIONS.md` に書く。
