# 公開の準備

このリポジトリは公開する前提で書く。ここに書いた条件を全部満たしたら、public にしてよい。
毎日の報告の冒頭に「公開の準備: 残り N 件」を書き、0 になった日に知らせる。

## 書かないもの（今後もずっと）

コード、コメント、文書、コミットメッセージ、試験、エラーメッセージのどこにも書かない。
判断の基準は「このリポジトリが明日公開されても困らないか」。

| 書かないもの | 代わりに書くもの | 止める所 |
|---|---|---|
| 本物のメールアドレス・氏名・アカウント ID・住所・電話 | ダミー（`user@example.com`、`C:\Users\user`） | `test/publishing.test.ts` |
| 公開していない別のリポジトリの名前 | 「別のリポジトリ」 | `test/publishing.test.ts` |
| 鍵・トークン・パスワード・接続文字列 | 環境変数の名前だけ。試験の値は見て分かる作り物（`ghp_abcdef…`） | pre-push の秘密の走査 |
| 利用者が言ったこと・どう反応したか | 自分がやったことと、その結果 | `test/publishing.test.ts`（決まった言い方）と目で見る |
| 作業中の愚痴・人への否定的な言い方・大げさな言い回し | 起きたことと直し方を、平らに | 目で見る |
| 勤め先の名前・社内の決まり・社内のホスト名 | 一般的な言い方（「管理された PC」） | 目で見る |
| 使ったモデルの名前の署名（文書の中） | 書かない。コミットの trailer だけは可 | 目で見る |

読む人は、このプロジェクトを初めて見る人。独自に作った一字の言葉（窓・網・口・札など）を使わず、
その分野で普通に使う言葉を使う（`test/wording.test.ts` が増やさせない）。散文で `**` の強調を使わない。

## 公開してよいかの判定

| # | 条件 | 状態 |
|---|---|---|
| 1 | いまのファイルに本物のメールアドレス・利用者名と、公開していない別のリポジトリの名前が無い（`.claude/` を除く） | 済（アドレスと別のリポジトリの名前は試験で止めている。全角も半角に揃えて見る。全角で書いた利用者名が 4 ファイルに残っていたのを 2026-10-11 に直した。利用者名そのものは試験で止められない＝名前をリポジトリに書けないので、目で見る） |
| 2 | 利用者の発言・反応を書き留めた箇所が無い（`CLAUDE.md`、`docs/`、`.claude/never-again.md` など） | 済（決まった言い方は試験で止めている。言い換えた形は目で見る） |
| 3 | 社内向けの記録（`docs/reports/`、`AdaptiveAIStudio-bug-report.md`）の扱いを決めて、片づけてある | 済（`docs/reports/` は開発の記録として公開に含め、上の決まりで書く。古い調査レポートは消した） |
| 4 | `.claude/` の中の別のリポジトリの名前（配る元で直す）と、`.claude/` を公開に含めるか | 残り |
| 5 | README を初めて読む人が読める（独自の言葉と `**` を直してある） | 済 |
| 6 | CLAUDE.md と主な文書（HANDOFF・HARNESS・ROADMAP など）の言い回しを直してある | 済（`docs/DECISIONS.md` は記録として残し、造語は残る。コードの造語は `test/wording.test.ts` の上限で減らしていく） |
| 7 | 社用PC向けの特殊な処理を外し、普通の置き場所にしてある（`docs/DECISIONS.md` 2026-10-10） | 済（Windows の実機では未確認。土曜の CI で見る） |
| 8 | 過去の履歴の中身からメールアドレスを消してある（作成者の欄は残す。force push を 1 回） | 残り（書き換えは用意した。押すのは利用者の判断。下の「8 の手順」） |
| 9 | 履歴全体を秘密の走査に掛けて、本物が 0 件 | 書き換えた複製で通した（2026-10-11。本物の鍵は 0 件。当たったのは試験の作り物と README の書き方の例だけ）。8 を押した後に、押したものでもう一度通す（`node scripts/scan-history.mjs`。消したファイルの古い中身も見る） |

`docs/DECISIONS.md` は記録として残す。全部は書き直さず、2 に当たる箇所と読めない言い回しだけ直す。

## 8 の手順

`scripts/scrub-history.mjs` が、origin から新しく複製したフォルダの中だけで履歴を書き換え、消えたかを数える。
元の複製と origin には触らない。押すのは結果を見てから、人が行う。

```
node scripts/scrub-history.mjs --address <消すアドレス> --noreply <ID>+<名前>@users.noreply.github.com --out <空のフォルダ>
```

- 中身とコミットメッセージの中のアドレスは `user@example.com` に置き換える
- 作成者・コミッターの欄は名前を残し、アドレスだけ GitHub の noreply に置き換える
- 消すアドレスはリポジトリに書かない（引数で渡す）

2026-10-11 に手元で一度通した結果（押していない）:

- 全部のブランチとタグ（59 件）、コミット 1128 件を書き換え、中身・メッセージ・作成者の欄に残ったアドレスは 0 件
- ブランチとタグの先頭の中身は、58 件が元と同じ。1 件（`claude/ci-local-first`）は、アドレスを置き換えた 3 行だけが違う
- 書き換えた複製の `git fsck` は通った
- 書き換えの途中で `fatal: refusing to create malformed object` が一度出た。書き換えは最後まで進み、上の確かめは通ったが、どのコミットで出たかは確かめていない
- 秘密の走査（9）で、古い履歴の 2 ファイル（1051 件のコミット）に Windows の利用者名を含む道が残っているのが見つかった。全角で書かれていたので、半角だけを探す数え方では「消えた」と言っていた。`--also` で消す文字列を足せるようにし、渡した文字列とアドレスの全角の綴りも自動で消して数えるようにした

押すときの形（利用者名も消す）:

```
node scripts/scrub-history.mjs --address <消すアドレス> --noreply <ID>+<名前>@users.noreply.github.com --also <利用者名> --out <空のフォルダ>
```

押すと、全部のコミットの番号が変わる。開いている PR と、ほかの複製は使えなくなる（取り直しが要る）。
