# 自発性 — LLMを動かす場所ではなく、AIが動く場所

## 0. 何を作っているのか

| | それは何か |
|---|---|
| LM Studio / Ollama | LLMを動かす場所。頼めば答える |
| Cursor / Claude Code | 頼めば作業する。頼まなければ止まっている |
| AdaptiveAIStudio | AIが動く場所。頼まなくても考えている |

違いは自発性の一点にある。
依頼を待つだけなら、それは実行環境であってスタジオではない。

> せっかくローカルで動けるんだから動き続けてよ

クラウドでは待機中に考えさせると課金が積み上がる。
ローカルは電気代だけなので、待機中に何もしないことが損失になる。

## 1. 流れ

```
利用者が入力していない（待機中）
  ↓ 30秒
手がかりを探す        ← 機械。モデルを使わない
  ↓
一つ選んで調べる      ← モデル。読み取りのみ。書き込み権限は渡さない
  ↓
提案としてまとめる
  ↓
承認待ちに積む        ← 実行しない
  ↓
利用者が /do で実行を決める
```

実際の動作:

```
依頼> （何も入力せず放置）

  考え中: src/auth.mjs に中身が空の catch が 1 件
  💡 提案 p001: login の catch が空で認証失敗の原因が消える
     src/auth.mjs の catch が空のため、verify が投げた例外が握り潰され null だけが返る
     /proposals で詳細、/do p001 で実行
```

## 2. 手がかりは事実から拾う

「なんとなく改善できそう」は雑音になる。
確認できる事実だけを手がかりにする。

| 手がかり | なぜ拾うか | 優先度 |
|---|---|---|
| 中身が空の `catch` | 失敗が表に出ない。原因が消える | 高 |
| `TODO` / `FIXME` / `HACK` | 書いた本人が「後で」と思った所 | 中 |
| テストの無い実装 | 検査されていないことは事実として分かる | 中 |
| 未コミットの変更 | 今まさに作業中のもの | 中 |
| 600行を超えるファイル | 読めない＝直せない | 低 |

この探索にモデルは使わない。 事実の収集は機械の方が速く、確実で、無料。
モデルは「裏を取る」「本当に問題か判断する」に使う。

## 3. 自発性と暴走は紙一重

自分で気づいて自分で直す、は行き過ぎ。
そこで気づくことと、やることの間に必ず承認を挟む。

| 段階 | 誰が決めるか |
|---|---|
| 何を調べるか | AI |
| 問題かどうか | AI |
| 実行するか | 利用者 |

調査担当には書き込みツールを渡さない。
「変更しないでください」と書くのではなく、権限として持たせない。
権限が無ければ事故は起きない。

## 4. 無駄に回さない仕掛け

自走させると、放っておけば同じ所を延々と調べ続ける。
計算が無料でも、それは成果ゼロの周回でしかない。

| 仕掛け | 内容 |
|---|---|
| 調査済みの記録 | 提案にならなかった（問題なしだった）手がかりも覚える |
| 内容の指紋 | ファイルの状態を指紋に混ぜ、変わったときだけ調べ直す |
| 発見の重複判定 | 別の手がかりから同じ発見に至っても、提案は1つにまとめる |
| 未処理の上限 | 溜まった提案が上限に達したら、それ以上は調べない |
| 入力の優先 | 考えている最中に入力が来たら、そちらを優先する |
| 間合い | 前の思考から既定10分は、次を始めない |
| 変更あたりの上限 | 一つの変更について、変更由来の思考は既定2回まで |

とくに重複判定を手がかりの指紋だけで行うと取りこぼす。
「テストが無い」から調べ始めて「catchが空」を見つけることがあるため、
提案の中身でも重複を見る。

### なぜ間合いが要るか

予算（1時間あたりの総コスト）だけでは、それを一息に使い切ることを止められない。
一つの変更は複数のモードの前提を同時に満たすため、
待機のたびに RECON → PATROL → RETROSPECT → FORECAST → WHAT-IF と続けざまに走り、
何も頼んでいないのに報告だけが並ぶ。読む側にとっては、
1時間に6回より、数分で6回の方がずっとうるさい。

そこで思考には二つの間合いを置く。

- 時間の間合い: 前の思考から10分は次を始めない（`minGapMinutes`）
- 変更の間合い: 同じ変更について、変更由来の思考は2回まで（`maxPerChange`）

モードは、何をきっかけに考えるかで二つに分かれる。

| きっかけ | モード | 変更あたりの上限 |
|---|---|---|
| 変更 | RECON・PATROL・RETROSPECT | かかる |
| 時間 | BRIEFING・FORECAST・WHAT-IF | かからない |

時間で起きるものは、変わっていなくても意味があるので上限の対象外。
ただし静かな時間の埋め草にならないよう間隔は長く取る
（FORECAST 90分・WHAT-IF 3時間・BRIEFING 6時間）。

立ち上げ直しても間合いは引き継ぐ。再起動すれば喋り出す、では意味がない。

## 5. 設定

```jsonc
{ "initiative": {
  "enabled": true,      // 既定
  "idleSeconds": 30,    // 何秒待機したら考え始めるか
  "leadsPerCycle": 1,   // 1回で扱う手がかりの数
  "maxOpen": 10,        // 未処理の提案がこれに達したら止める
  "budgetPerHour": 12,  // 1時間に使ってよい思考の総コスト
  "minGapMinutes": 10,  // 前の思考から次までに空ける最短の間隔
  "maxPerChange": 2     // 同じ変更について、変更由来の思考は何回まで
} }
```

| コマンド | 内容 |
|---|---|
| `/proposals` | 未処理の提案 |
| `/do <id>` | 提案を実行する（そのまま依頼として流れる） |
| `/reject <id>` | 却下する（以後、同じ提案はしない） |
| `/think` | いま考えさせる |
| `/idle` | 思考モードの実績と、次に考えてよくなるまでの時間 |

## 6. ここから先

今の自発性は手元のコードを見るところまで。
本来やりたいのは、もっと広い。

| 段階 | 内容 | 状態 |
|---|---|---|
| 手元を調べる | コードから手がかりを見つけて提案する | 動作 |
| 実行して確かめる | テストを流し、失敗から手がかりを得る | 一部（検証ループ） |
| 外から情報を取る | ドキュメント・依存パッケージの更新・エラーの調査 | 未実装 |
| 継続的に考える | 日をまたいで、前に考えたことの続きをやる | 未実装 |
| 提案を育てる | 却下された理由を覚え、提案の質を上げる | 未実装 |

外から情報を取るが入ると、
「調べる → 分かる → さらに調べる」の輪が閉じて、本当に自走し始める。
