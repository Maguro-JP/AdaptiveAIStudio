# 画面

## 配置はコードではなくデータ

好みは人によって違う。会話だけ大きく出したい人もいれば、
進行中の作業と記憶を常に見ていたい人もいる。
作り手が一つの正解を決めてしまうと、そこで自由度が終わる。

だから配置は `.aas/layout.json` に置く。理由は三つ。

1. **自分で書き換えられる** — ファイルを直せば配置が変わる
2. **AIに頼んで変えられる** — AIが扱えるのは、コードよりデータ
3. **壊しても戻る** — 読めない配置は直して表示する。真っ白にしない

3 が一番効く。配置をAIに触らせる以上、壊れた配置は必ず来る。
そこで画面が真っ白になるなら、AIには触らせられない。
**「壊れても表示できる」ことが、「AIに任せられる」ことの前提**になる。

## 変え方は三つ

| 手段 | どうやるか |
|---|---|
| 選ぶ | `⚙ 設定`（Ctrl+,）の「配置」「見た目」から切り替える |
| 掴む | 仕切りを掴んで動かす。比率はその場で保存される |
| 書く | 設定 → 配置 →「配置を直接いじる」で JSON をいじる |

そして四つ目が本命。

```
> 記憶を左に大きく出して、会話は右下に小さくしておいて
```

AIに頼めばいい。`.aas/layout.json` はただのファイルなので、
書き換えの対象になる。壊れていれば、画面側が直して表示する。

## 配置の書き方

```json
{
  "id": "custom",
  "name": "自分の配置",
  "theme": "auto",
  "density": "comfortable",
  "panels": [
    { "id": "chat", "kind": "conversation" },
    { "id": "mem",  "kind": "memory", "title": "覚えていること" }
  ],
  "root": {
    "type": "split", "direction": "row", "sizes": [0.7, 0.3],
    "children": [
      { "type": "panel", "panel": "chat" },
      { "type": "panel", "panel": "mem" }
    ]
  }
}
```

`split` の入れ子で表すので、段組みでも三分割でも好きな形になる。
同じ場所に重ねたいときは `tabs`。

置ける中身:
`conversation` / `plan` / `roster` / `memory` / `proposals` / `duties` / `models` /
`changes` / `preview` / `checks` / `log` / `note`

足すときは三箇所そろえる。`src/ui/layout.ts` の `PANEL_KINDS`、
`panels.js` の関数、同じく `TITLES` の見出し。**一つ抜けると、その板だけ
空になる。**落ちないので気づけない（実際に `preview` の見出しが抜けていた）。
`test/panel.test.ts` が、三つそろっているかを見る。

増やすときは `src/ui/web/panels.js` に関数を一つ足す。
他を触らなくていいことが、いじりやすさになる。

## 壊れた配置をどう直すか

| 壊れ方 | どうなるか |
|---|---|
| 読めない JSON | 既定の配置に戻す |
| 存在しない中身を置いた | その場所だけ外す |
| 同じ中身を二箇所に置いた | 後の方を外す |
| 置き場所の無い中身 | 捨てずに右端へ寄せる |
| 幅の数が合わない | 均等に割り直す |
| 幅の合計が 1 でない | 比率を保ったまま揃える |
| 分割の中身が一つ | 分割を畳む |
| `type` の書き忘れ | 形から読み取る |
| **知らない種類** | 消さずに「そういう中身はまだありません」と出す |

最後の行が方針をよく表している。**消さない**。
何を置こうとしたのかが画面に残る方が、直しやすい。

直した内容は必ず知らせる。黙って直すと、次も同じ壊れ方をする。

## 作りの方針

**枠組みを持ち込まない。**
この場所は何年も動き続けることを目的にしているので、
数年で作法が変わるものに画面を預けたくない。
素の HTML と ES モジュールなら、組み立ての手順すら要らない。

**外に公開しない。** 待つのは `127.0.0.1` だけ。
認証も暗号化も入れないのは、手を抜いたのではなく、外に出さないから要らない。

**画面は状態を持たない。** 保存されているものだけを読んで組み立てる。
持たせると、CLI で動かしたときと画面で見たときで食い違う。

## 起動

```
npm run ui
```

`start.cmd` / `start.sh` をダブルクリックして 1 を選んでも同じ
（`start.cmd ui` と書けば、選ぶところを飛ばして画面だけ開く）。

## 窓は入口。道具は画面に置く

点検（この環境を見てもらう・検査・片づけ）とモデルの設定は、
**画面の `⚙ 設定`（Ctrl+,）の中にある。**

立ち上げたあとは cmd の窓が塞がるので、そこに並べると、動かしている
最中に見たいものが見られない。窓に残してあるのは、画面をひらく・
新しくする・困ったとき（doctor）の三つだけ。

| 節 | 中身 |
|---|---|
| 情報 | 版・Node・この機械・置き場（根/記録/モデル/実行ファイル）・モデルの土台 |
| 見た目 | 土台を選ぶ／色をいじる |
| 配置 | 型を選ぶ／直接いじる |
| モデル | 動かし方（ollama / llamacpp / inproc）・GGUF の置き場・取ってくる |
| 点検 | doctor・検査・この機械で確かめる・片づけ・モデル |

**版を情報のいちばん上に置いてある。**古いものを新しいと思って確かめるのが、
いちばん無駄になるため。

新しくするときは、コマンド一覧（Ctrl+K）の「更新を確認する」。
何が入るのかを一覧で見せてから取り込みます。
取り込んだ後は、動いているコードと置いてあるコードがズレるので、
「いま立ち上げ直しますか」と訊きます。断っても、設定の「立ち上げ直す」から
いつでも立ち上げ直せます（黙って再起動はしません。訊いてから）。
git の無い機械（配布物）では、取ってくる先（Releases）と入れ替え方を出します。
ブラウザは自動で開く（開けない環境なら場所だけ出す）。

## 見た目は着替えられる

配置と色は**別々に持つ**。`.aas/layout.json` と `.aas/theme.json`。
「配置はそのままで色だけ変えたい」が、気分としては一番多いから。

| 名前 | どういう日に |
|---|---|
| **Slate** | 既定。落ち着いた暗色。一日中見ていられることだけを狙っている |
| **Paper** | 明るい昼向け |
| **Dusk** | 暖色寄りの夜向け。刺激を落としたい日に |
| **Cyber** | 光る夜。気分を上げたい日に |

上の帯の選択欄で切り替わる。選んだものは保存される。

### 既定を落ち着かせている理由

地は真っ黒にしない。文字も真っ白にしない。
差が強すぎると、長時間で目が疲れる。
目を引く色（accent）は、目を引かせたい一箇所だけに使う。
全部が目立つ画面は、何も目立たない画面と同じ。

間合いは一つの尺度（4/8/12/16）から作る。ばらばらの数字を置かない。

### 自分の色にする

「色」から、項目ごとに変えられる。**触っているそばから画面に映る**。
保存しなければ元に戻る。触っただけで決まってしまわないように。

変えられるのは色だけではない。角の丸み、枠の間、書体、字の大きさ、行間、影。

```json
{
  "base": "slate",
  "tokens": { "accent": "#ff8800", "radius": "2px", "fontMono": "'Fira Code', monospace" }
}
```

`base` の上に、変えたところだけ乗る。全部書く必要は無い。

### 受け取らない値がある

この値は CSS へそのまま流れるので、**必ず検める**。
`}` や `;` や `url(` を含むものは、色の設定ではないので通さない。
ここを素通りさせると、色の設定という顔をして何でも書けてしまう。

弾いたことは黙らない。黙って消すと、なぜ効かないのか分からなくなる。

```
・accent の値は受け取れません（色や長さとして読めない書き方です）。
・nope という項目は無いので無視しました。
```

## 端末の写しにしない

流れる文字をそのまま写すなら、端末で足りる。
起きたことを**札**にして、種類ごとに形を変える。

| 起きたこと | 見え方 |
|---|---|
| 頼んだこと | 右に寄せた札。話の区切りがひと目で分かる |
| 返ってきた言葉 | 幅を絞って行間を広げる。読ませたいものだから |
| 道具の呼び出し | 一行に畳む。開けば結果が出る。失敗したものだけ最初から開く |
| **書き換え** | **差分そのもの**。赤と緑、行番号つき |
| 検収 | 畳まない。人が見る前提の一枚だから |
| 承認 | 差分を添えた札。押されるまで向こうは止まっている |

### 差分は、赤と緑で、行番号つきで

「+12 -3」とだけ言われても、何が起きたのかは分からない。
変わった行そのものを出す。これが読めるかどうかで、任せられるかどうかが決まる。

- **1本で見る**（unified）と**左右で見る**（split）を切り替えられる
- 変わっていないところは畳む。全部見せると、変わったところが埋もれる
- ただし前後3行は残す。何の周りの変更なのかが分からなくなるため
- そのままコピーできる

### 「変更」の欄

その対話で書き換えたファイルが一箇所に集まる。
会話を遡らないと分からない、では見落とす。
開いたときに初めて差分を描く。閉じたままのものに手間をかけない。

### 手が届くところ

| 操作 | |
|---|---|
| `Enter` | 送る（`Shift+Enter` で改行） |
| `Ctrl+K` | コマンド。見た目も配置もここから引ける |
| `Ctrl+/` | 入力欄へ戻る |
| 下の帯 | 使っているモデルと、いま動いているかどうか |

読んでいる途中で勝手に飛ばさない。
下まで見ているときだけ追いかけ、そうでなければ「新しい動きへ ↓」を出す。

## 開いておくだけで動く

画面を開いたまま席を立っても、この場所は考え続ける。
気づいたことは提案として溜まり、会話にも「提案」の欄にも並ぶ。

その場で **[やってもらう]** を押せば、それが依頼になって作業が始まる。
**[却下]** を押せば、その考え方は次から選ばれにくくなる。

考えている間に手は出さない。承認を必ず断る作業者に考えさせているので、
溜まるのは提案だけ。押すまで何も起きない。

## 列は揃える

一覧の列は、行ごとに幅が動かないようにしてある。
幅が動くと、読むたびに目が探し直すことになる。
揃えるのは見た目の好みではなく、読み取りの速さの問題。

行の中の列を一覧全体で共有し（subgrid）、足りない列は空で埋める。
埋めないと、次の行がずれる。
数は右で揃える。桁が縦に並ぶ。
はみ出す文字は末尾を切る。**列がずれるより、末尾が切れる方がまし**。

## 画面から実際に動かす

指示を書いて Enter で、そのまま作業が始まる。

```
> memo.txt を書き換えて
· read_file memo.txt
✓ 1 元の中身
· write_file memo.txt
  変更: memo.txt
  --- a/memo.txt
  +++ b/memo.txt
  @@ -1,2 +1,2 @@
  -元の中身
  +書き換えました
  [許可] [拒否]
```

**承認は画面の押しボタンになる。** 押されるまで、向こう側は本当に止まって待っている。
拒否すればファイルは変わらない。作業は続き、拒否されたことが作業者に伝わる。

答えが返らないまま10分経ったら、拒否として扱う。
**返事が無いことは、許可ではない。**

`中断` はいま動いているものを止める。対話は続く。

### 分解して並列に働かせる

`/plan` で始めると、依頼が分解され、担当が割り当てられ、同時に走り出す。

```
> /plan memo.txt を直して
計画を直しました: 一人に任せないため、確かめる工程を 2 件足しました。
方針: memo を調べてから直す
[t1]   scout     @main（すぐ着手）   memo.txt の中身を読んで報告する
[t2]   worker    @main ← t1 の後     memo.txt を書き換える
[t1_2] librarian @main ← t1 の後     （裏を取る）
[t2_2] breaker   @main ← t2 の後     （書かれたものを確かめる）
▶ t1 着手 → ✓ → t2 と t1_2 が同時に着手 …
検収: 判断をお願いします
```

右上の「進行中」に、各件の状態が並ぶ。
待ち・進行中・完了・失敗・未実施が、色と記号で分かる。

## 対話の核を入口から切り離す

これまで対話の手順は CLI の中に書かれていた。動きはするが、画面から同じことを
しようとすると、同じ手順をもう一度書くことになる。書けば必ずずれる。

そこで核を `src/core/session.ts` に出した。
入口（CLI・画面・その先の何か）は出来事を受け取って見せるだけで、
何が起きるかは核だけが決める。

承認も核では決めない。呼ぶ側に訊く。
端末なら「y/N」、画面なら押しボタンになる。
**訊かずに進めない**という一点だけを、核が守る。

## 入口が二つでも、手順は一つ

手順は `Session` だけが持っている（[対話の核](CORE.md)）。
CLI も画面も、出てくる出来事を見て描くだけ。

同じ依頼を CLI で流しても画面で流しても、同じ順番で同じことが起きる。
描き方が違うだけで、**手順が二つに割れていない**。

### 画面でも「書いて終わり」にしない

通常の依頼でも、作業のあとに検証が回る。失敗したらその内容を渡して直させ、
通るまで繰り返す。作業前から落ちていた失敗は、そう言って切り分ける。

```
作業前の状態: npm test → 通っています
· write_file src/x.ts
  ✓ 更新: src/x.ts（+12 -3）
検証 1回目: npm test
✗ 検証に失敗（1回目）
修正させています…
· write_file src/x.ts
検証 2回目: npm test
✓ 検証を通過しました (8.4s)
完了 (63.1s)
```

詳しくは [対話の核](CORE.md)。

## 何も入っていないところから

```
git clone -b claude/adaptive-ai-studio-architecture-y12imi https://github.com/Maguro-JP/AdaptiveAIStudio.git
cd AdaptiveAIStudio
npm run doctor      # 何が足りないかを見る
npm run ui          # 開く（モデルが無くても開く）
```

`npm install` は要りません。実行時の依存はゼロで、ビルドもありません。

**モデルが無くても画面は開きます。** 配置や色を触ったり、人員や日課を眺めたり
はできます。考えさせるにはモデルが要ります。
