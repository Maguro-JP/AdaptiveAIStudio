# 対話の核

入口（CLI・画面・その先の何か）から切り離した本体。
`src/core/session.ts`。

## なぜ切り離したか

手順が入口の中に書かれていると、入口を増やすたびに同じ手順を書き直すことになる。
**書けば必ずずれる。** 端末では検証が回るのに画面では回らない、
画面では記憶を引くのに端末では引かない、という食い違いが必ず生まれる。

だから核を一つに決めた。
入口は出来事を受け取って描くだけで、**何が起きるかは核だけが決める**。

```
利用者 ─┬─ CLI  ─┐
        └─ 画面 ─┴─→ Session ──→ 作業者・道具・ハーネス・記憶
                        ↑
                     承認だけは入口へ訊き返す
```

## 二つの入口

`Session` が持つ手順は二つだけ。

| 手順 | 何をするか |
|---|---|
| `send()` | 一人で最後までやる。思い出す → 作業前を控える → 作業 → **検証して直させる** → 決着 |
| `plan()` | 分解して複数人で当たる。思い出す → 分解 → 割り当て → 並列実行 → 検査 → 検収 |
| `think()` | 暇なときに考える。何を考えるかはスケジューラが決める。結果は提案として溜める |

同じ依頼を CLI で流しても画面で流しても、同じ順番で同じことが起きる。
描き方が違うだけ。

## 承認だけは核が決めない

呼ぶ側に訊く。端末なら `y/N`、画面なら押しボタン。

核が守るのは **訊かずに進めない** という一点だけ。
どう訊くかは入口の仕事で、訊くかどうかは核の仕事。

## `send()` の中身

1. **思い出す** — 依頼に関係する記憶と、前に駄目だった手を添える
2. **作業前を控える** — テストの一覧（改ざん検出の基準）と、いまの成否（責任の切り分け）
3. **作業** — 道具を呼ばせる。書き込む前には控えを取る（打ち切ったとき戻せるように）
4. **検証** — 書いて終わりにしない。失敗したらその内容を渡して直させ、通るまで繰り返す
5. **決着** — 通らないまま打ち切ったなら巻き戻す。実測を溜め、規則の効き具合を記録する

### 前からの失敗を、今回のせいにしない

2 で控えた成否と突き合わせる。作業前から落ちていたなら、そう言う。

```
作業前の状態: npm test → 作業前から失敗しています
…
この失敗は作業前から出ています。今回の作業が原因ではありません。
```

これをやらないと、直せない失敗を延々と直させることになる。

### 打ち切りは三つで測る

回数・時間・進捗。無人で何時間でも回すが、青天井にはしない。
同じ失敗を繰り返し始めたら、そこで止める。

## 権限は核が配る

役職ごとに、渡す道具を変える。

```
read    read_file / list_files / search_text
write   write_file
execute run_command
network fetch_url        ← 情報担当だけ
```

禁じる文言ではなく、**手段の有無**で決める。
調べるだけの担当は、書き込む道具を持っていないので書けない。

## 暇なら考える

席を立っても、この場所は動き続ける。

```
［PATROL］巡回検査 — WARDEN（本日分の DAILY SWEEP がまだです）
［PATROL］報告することはありませんでした
［DIGEST］通し確認 — CURATOR（本日分の CARRY-OVER がまだです）
［AGENDA］段取り — ARCHITECT（本日分の PLAN AHEAD がまだです）
💡 greet.js のバージョン表記が二箇所にある
   片方だけ直すと食い違う。1.0.0 と 2.0.0 の混在を確認した
   → バージョンの定義を一箇所にまとめる     [やってもらう] [却下]
```

### 考えるが、手は出さない

思考には**承認を必ず断る**作業者を渡す。
考えた結果は提案として溜まるだけで、実行はしない。

勝手に考えてくれるのと、勝手に手を動かされるのは、別の話。
採るかどうかは人が決める。押した時点で、それは依頼になる。

### 無駄に考えない

「暇なら考える」は「常に考える」ではない。核が三つで止める。

| 止め方 | 何を防ぐか |
|---|---|
| 前提条件 | 何も変わっていないのに考え直す。前回と同じ結論にしかならない |
| 予算 | 1時間あたりの量。計算は無料でも、読む側の集中力は有限 |
| 実績 | 採用されなかった考え方は、だんだん選ばれなくなる |

日課（DAILY SWEEP / CARRY-OVER / PLAN AHEAD / WEEKLY REVIEW）は別枠で、
変化が無くても時間で起きる。「今日まだ全部見ていない」が分かる状態を保つため。

### どちらの入口でも同じように溜まる

提案も、日課の記録も、思考の実績も核が持つ。
端末で考えさせても画面で考えさせても、同じところに溜まる。
画面を開いたまま席を立てば、戻ってきたときに提案が並んでいる。

## 入口が足りないときは

`SessionEvent` を受けて描くものを書けば、それが新しい入口になる。
核には手を入れない。手を入れる必要が出たなら、それは核の側の不足。
