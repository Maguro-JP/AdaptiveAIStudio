# 失敗の記録

起きたことだけを書く。一般論は書かない。
1件は4行。場面は「次から」を差し込むときの索引になるので、短い名詞で書く。
新しいものを上に足す。

## 2026-09-22 CI が赤いまま PR をマージした
場面: マージ
起きたこと: RuleCrawler #3 を `mergeable_state: unstable` のままマージした。verify は落ちていた
判定の誤り: PR の状態を取ったのに、チェックの結果を見ずにマージへ進んだ
次から: マージの前に check runs を見る。赤なら止まる。原因が枠切れでも、確かめてから進む

## 2026-09-22 depth 1 の clone でブランチが1本だと決めた
場面: ブランチ、配布
起きたこと: RuleCrawler に `main` があるのに「唯一のブランチ」と報告した。`--depth 1` は既定ブランチしか取らない
判定の誤り: 手元の `git branch -r` を全ブランチの一覧だと思った
次から: ブランチの有無は `git ls-remote --heads origin` か API で見る。手元の clone は根拠にしない

## 2026-09-22 既定ブランチに配って、本人の main に届かなかった
場面: 配布、ブランチ
起きたこと: 既定が `claude/...` の作業ブランチだったので Raphael はそこへ配り、`main` で作業する本人には見えなかった
判定の誤り: 既定ブランチの名前が変だと気づいて書いたのに「動きはする」で流した
次から: 既定が `claude/` で始まるなら `main` か `master` に配る。変だと気づいたら、流さずその場で確かめる

## 2026-09-22 ステップ無しで数秒で落ちるジョブを、コードのせいだと疑った
場面: CI
起きたこと: Actions の枠切れ。ジョブにステップが1つも無く、3秒で失敗、ログは 404
判定の誤り: 最初にコードを疑った。手元で通したのは正しかったが、順番が逆
次から: ステップ無し・数秒・ログ 404 なら、コードより先に Billing の Actions 使用量を疑う

## 2026-09-19 スキルがセッション開始時にしか読まれないと言った
場面: スキル
起きたこと: 作業ツリーにファイルが現れた時点で読まれる。同じセッションで3回それを見ていた
判定の誤り: 自分で観測した事実より、思い込みを先に出した
次から: 仕組みの説明は、このセッションで観測したことに限って書く

## 2026-09-18 squash マージのあと同じブランチに積んでコンフリクトさせた
場面: 配布、マージ
起きたこと: `ciel-sync` を使い回し、21 リポジトリが「merge commit cannot be cleanly created」
判定の誤り: squash マージで履歴が分かれることを考えなかった
次から: 配布ブランチは毎回既定ブランチから作り直す。`-f` で push するなら使い回す理由は無い

## 2026-09-18 失敗を数えずにジョブを緑にした
場面: CI、配布
起きたこと: 21 件マージできないまま、ジョブは success で終わっていた
判定の誤り: 「PR は作れた」を成功にしていた
次から: 目的（入ったか）が達成されなければ失敗にする。緑は「見に行かなくていい」の意味

## 2026-09-04 「明日確認できます」と言って見に行かなかった
場面: 報告
起きたこと: 土曜の定期実行が失敗し、2週間誰も気づかなかった
判定の誤り: 確認の約束に、見に行く仕組みを付けなかった
次から: 期限つきの確認は `send_later` か Routine をその場で入れる。入れられないならそう言う

## 2026-09-04 dry run で本番を保証した
場面: 配布
起きたこと: dry run は通ったが、本番は push と PR 作成で3回続けて失敗した
判定の誤り: dry run が書き込みの経路を通らないことを忘れた
次から: 本番の前に1件で本番を通す。dry run は対象の選び方の確認

## 2026-09-04 ステージが空なら gitignore だと決めた
場面: 配布
起きたこと: 既に同じ内容だっただけ。gitignore と誤判定して「配れません」と報告した
判定の誤り: 事実を取れるコマンドがあるのに推測した
次から: `git check-ignore` で聞く。推測で判定を書かない

## 2026-08 作業ツリーが別ブランチを見ていたのを、クライアントのせいにした
場面: ブランチ、スキル
起きたこと: スキルは `master` にあり、作業ツリーは `develop` だった。デスクトップ版の制約だと断定した
判定の誤り: ブランチを見る前に原因を断定した
次から: 「見えない」と言われたら、最初に `git branch --show-current` と `ls .claude/skills` を見る
