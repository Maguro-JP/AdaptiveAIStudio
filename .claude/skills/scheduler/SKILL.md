# スケジューリング

時刻で起こすものは Routine（cron）で作る。1時間以内の繰り返しは `loop`。
Routine の1回の起動は1セッション分のトークンを使う。回数は必要最小限にする。

## 決まり

| 決まり | 理由 |
|---|---|
| cron は UTC で書く。JST から 9 時間引く | Routine は UTC で評価される。日付をまたぐなら曜日と日もずらす |
| 分は必ず 0 | 切りの悪い時刻に起こさない。`*/N` はこの環境では作成時刻に固定されるので使わない |
| 複数回なら時刻を列挙する | `0 0,6,12 * * *` と書く。`0 */6 * * *` は使わない |
| 同じセッションに起こす（自分自身に結びつける） | 新しいセッションで起こすと、リポジトリも connector も無い空の環境で始まり、clone できない。試して確かめた |
| プロンプトにスキル名と引数を必ず入れる | 圧縮で前の文脈が薄れる。プロンプトだけで何をするか分かるようにする |
| 名前は「スキル名 引数」にする | 一覧で何が動くか分かる。例: `long-dev weekly` |
| 消さずに無効にする | 再開が楽で、履歴も残る |

JST と UTC の対応。

| JST | UTC |
|---|---|
| 09:00 | `0 0` |
| 12:00 | `0 3` |
| 21:00 | `0 12` |
| 00:00 | `0 15`（前日） |

## 起きたセッションが動くための条件

2026-09-24 に Daikenja で試して確かめたこと。

| 起こし方 | 結果 |
|---|---|
| 新しいセッションで起こす（create_new_session_on_fire） | 設定が `sources: []` `mcp_servers: []`。リポジトリも GitHub の connector も add_repo も無い。clone できず、何も書けない。権限モードは auto だった |
| 同じセッションに起こす（自分自身に結びつける） | そのセッションのリポジトリ、connector、権限モードのまま再開する。このセッションの send_later がそれで、clone も push も通った |

だから Routine は「そのリポジトリを開いた auto モードのセッション」の中から、自分自身に結びつけて作る。
そのセッションがそのリポジトリの働き手になる。容器が回収されても、起きるときに作り直され、
リポジトリは clone し直される。会話は続くので、長くなれば圧縮される。

| 条件 | 外したときに起きること |
|---|---|
| そのリポジトリを開いたセッションの中で作る | 別のセッションから作ると、そのリポジトリが無い |
| auto モード（承認なし）のセッションで作る | 起きた側が承認待ちで止まり、誰も押さない |
| 自分自身に結びつける | 新しいセッションで起こすと空の環境になる |
| 作った直後に1回手で起こす | clone、変更、push、PR までできるのを見る。見るまで「動く」と言わない |

作る前に、今のセッションがその条件を満たしているか確かめる。満たしていなければ、
その旨を伝えて、条件を満たすセッションで作ってもらう。

## 手順

### 作る

1. 何を、どの周期で、何時（JST）に起こすかを1行で確かめる
2. cron に直す。UTC、分は 0、列挙
3. プロンプトを書く。対象リポジトリ（owner/repo）、スキル名、引数、止まる条件。同じセッションに戻ってくるので、前の文脈があってよい
4. 自分自身に結びつける（新しいセッションで起こさない）
5. 作ったあと一覧を見て、cron と次回の時刻が意図どおりか確かめる
6. その場で1回手で起こし、clone と最初の書き込みまでできるのを見る。できなければ Routine を無効にして原因を直す

### 見る

一覧を出し、名前・cron・有効か・次回・前回の結果を並べる。
前回が失敗なら、その Routine は仕事をしていない。原因を見る。
前回が成功でも「起きた」という意味しかない。試験の Routine は何も書けずに終わっても成功と記録された。
仕事ができたかは、リポジトリ側（ブランチ、PR、報告ファイル）で見る。

### 止める

無効にする。消さない。

## 定型

| 名前 | cron（UTC） | プロンプト |
|---|---|---|
| `long-dev` | `0 1 * * *` | long-dev E=23h を実行する。翌朝 09:00 まで回す |
| `dev-report daily` | `0 0 * * *` | dev-report daily を実行する。日報を書く。開発はしない |
| `dev-report weekly` | `0 0 * * 1` | dev-report weekly を実行する。週報と来週の計画。PR を整理する |
| `dev-report monthly` | `0 0 1 * *` | dev-report monthly を実行する。月報と今月の週ごとの計画 |
| `auto-dev 朝夕` | `0 0,9 * * *` | auto-dev E=1h を実行する。優先: <指示> |

報告の3つは揃えて作る。開発そのもの（long-dev）は Routine ではなく、セッションで回し続けるもの。

Raphael の配布は Actions の schedule で、Routine ではない。土曜 09:00 JST。

## 費用

| 周期 | 月の起動回数 |
|---|---|
| daily（報告） | 約30。報告だけなので短い |
| long-dev | 約30。1回が翌朝まで続く長いセッション |
| weekly | 4〜5 |
| monthly | 1 |
| 朝夕 | 約60 |

変更不要の日は調査だけで終わるので軽いが、ゼロではない。
Actions は PR を作った日だけ走る。private リポジトリは分数が課金される。

## 権限

自分自身に結びつけた Routine は、そのセッションのリポジトリと connector と権限モードで動く。
起きたセッションが「リポジトリに接続が無い」「認証できない」と言ったら、新しいセッションで
起こす設定になっている。作り直す。

## やらないこと

- 1時間以内の繰り返しを Routine にすること。`loop` を使う
- 「とりあえず毎時」で作ること。回数は仕事の周期に合わせる
- 同じ仕事の Routine を二重に作ること。作る前に一覧を見る

## 他のスキルとの関係

- 日報・週報・月報: `dev-report`
- 終わりの無い自律開発: `long-dev`
- 周ごとの作業: `auto-dev`
- 1時間以内の繰り返し: `loop`
