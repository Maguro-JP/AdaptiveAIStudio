# スケジューリング

時刻で起こすものは Routine（cron）で作る。1時間以内の繰り返しは `loop`。
Routine の1回の起動は1セッション分のトークンを使う。回数は必要最小限にする。

## 決まり

| 決まり | 理由 |
|---|---|
| cron は UTC で書く。JST から 9 時間引く | Routine は UTC で評価される。日付をまたぐなら曜日と日もずらす |
| 分は必ず 0 | 切りの悪い時刻に起こさない。`*/N` はこの環境では作成時刻に固定されるので使わない |
| 複数回なら時刻を列挙する | `0 0,6,12 * * *` と書く。`0 */6 * * *` は使わない |
| 毎回新しいセッションで起こす | 同じセッションに積むと会話が長くなり、1回ごとのトークンが増える |
| プロンプトは単独で読めるように書く | 新しいセッションは何も覚えていない。スキル名と引数を必ず入れる |
| 名前は「スキル名 引数」にする | 一覧で何が動くか分かる。例: `long-dev weekly` |
| 消さずに無効にする | 再開が楽で、履歴も残る |

JST と UTC の対応。

| JST | UTC |
|---|---|
| 09:00 | `0 0` |
| 12:00 | `0 3` |
| 21:00 | `0 12` |
| 00:00 | `0 15`（前日） |

## 起きたセッションが動くための条件

Routine から起きるセッションは、Routine を作ったセッションの環境と権限で動く。
ここを外すと、起きても clone できない、毎回承認で止まる、のどちらかになる。

| 条件 | 外したときに起きること |
|---|---|
| そのリポジトリを開いたセッションから作る | ソースに無いリポジトリは clone できず、403 や認証エラーで止まる |
| auto モード（承認なし）のセッションから作る | 起きた側も毎回承認待ちになり、誰も押さないので止まる |
| プロンプトに逃げ道を書く | 作業ディレクトリに無ければ `add_repo` で付けて clone する、と書く。資格情報を探しに行かせない |
| 作った直後に1回手で起こす | clone、変更、push、PR までできるのを見る。見るまで「動く」と言わない |

作る前に、今のセッションがその条件を満たしているか確かめる。満たしていなければ、
その旨を伝えて、条件を満たすセッションで作ってもらう。別のセッションから作った Routine は動かない。

## 手順

### 作る

1. 何を、どの周期で、何時（JST）に起こすかを1行で確かめる
2. cron に直す。UTC、分は 0、列挙
3. プロンプトを書く。対象リポジトリ（owner/repo）、スキル名、引数、止まる条件。先頭に「作業ディレクトリに <owner/repo> が無ければ add_repo で付けて clone する」を入れる
4. 新しいセッションで起こす設定にする
5. 作ったあと一覧を見て、cron と次回の時刻が意図どおりか確かめる
6. その場で1回手で起こし、clone と最初の書き込みまでできるのを見る。できなければ Routine を無効にして原因を直す

### 見る

一覧を出し、名前・cron・有効か・次回・前回の結果を並べる。
前回が失敗なら、その Routine は仕事をしていない。原因を見る。

### 止める

無効にする。消さない。

## 定型

| 名前 | cron（UTC） | プロンプト |
|---|---|---|
| `long-dev` | `0 1 * * *` | 作業ディレクトリに <owner/repo> が無ければ add_repo で付けて clone する。long-dev E=23h を実行する。翌朝 09:00 まで回す |
| `dev-report daily` | `0 0 * * *` | 同上の1行のあと、dev-report daily を実行する。日報を書く。開発はしない |
| `dev-report weekly` | `0 0 * * 1` | 同上の1行のあと、dev-report weekly を実行する。週報と来週の計画。PR を整理する |
| `dev-report monthly` | `0 0 1 * *` | 同上の1行のあと、dev-report monthly を実行する。月報と今月の週ごとの計画 |
| `auto-dev 朝夕` | `0 0,9 * * *` | auto-dev E=1h を実行する。優先: <指示> |

報告の3つは揃えて作る。開発そのもの（long-dev）は Routine ではなく、セッションで回し続けるもの。

Raphael の配布は Actions の schedule で、Routine ではない。土曜 09:00 JST。

## 費用

| 周期 | 月の起動回数 |
|---|---|
| daily（報告） | 約30。報告だけなので短い |
| long-dev | 約30。1回が翌朝まで続く長いセッション |
| weekly | 4〜5 |
| monthly | 1 |
| 朝夕 | 約60 |

変更不要の日は調査だけで終わるので軽いが、ゼロではない。
Actions は PR を作った日だけ走る。private リポジトリは分数が課金される。

## 権限

Routine のセッションは、作ったときのセッションと同じリポジトリと権限モードで動く。
push とマージをさせるなら、そのリポジトリを開いた auto モードのセッションで作る。
起きたセッションが「リポジトリに接続が無い」「認証できない」と言ったら、Routine を作った
セッションが条件を満たしていない。作り直す。

## やらないこと

- 1時間以内の繰り返しを Routine にすること。`loop` を使う
- 「とりあえず毎時」で作ること。回数は仕事の周期に合わせる
- 同じ仕事の Routine を二重に作ること。作る前に一覧を見る

## 他のスキルとの関係

- 日報・週報・月報: `dev-report`
- 終わりの無い自律開発: `long-dev`
- 周ごとの作業: `auto-dev`
- 1時間以内の繰り返し: `loop`
