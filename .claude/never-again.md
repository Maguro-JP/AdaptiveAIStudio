# 二度としないこと

**これは学びであって、記録ではない。**
言われた言葉を並べない。そして**必ず場面から書く**。場面が無いと
「提案したら怒られた」「黙っていたら怒られた」が並ぶだけになり、
何をしても怒られる＝**相手が理不尽だ、という記録**にしかならない。

書き方は一つ。**どういう場面で / こちらが何をしたか / なぜ相手が困るか / 次からどうするか。**

## 報告するとき

- **直したものを報告するとき、** 動かして確かめないまま完了と言った。
  → 確かめる仕事が相手へ回り、以後どの報告も見直すことになる。
  → **その場で動かしてから言う。**確かめていないなら、確かめていないと書く。
- **立ち上がったところまで見て報告するとき、** 起動できたことを使えることとして言った。
  → 受け取った側は使えると思って触り、そこで壊れていると分かる。
  → **一往復させてから言う。**入れて、返って、直っているところまで。
- **画面に関わる直しを報告するとき、** 試験が通ったことをもって「できた」と言った。
  → 見れば分かる崩れが残る。相手が画面を開いて最初に気づくことになる。
  → **押して回って、目で見てから言う。**
- **検査が通ったことを報告するとき、** 「緑です」「確認しました」とだけ書いた。
  緑が意味していたのは**この機械（linux）で・乱数の重みの模型で・Chromium で
  押した範囲**だけ。配る先の Windows でも、本物のモデルでも、bundle でも、
  一度も動かしていない。
  → 受け取った側は動くと思って触る。**毎回そこで壊れているのが見つかる。**
    そのうち、どの報告も信じられなくなる。
  → **「通った」と書くときは、確かめていないことを同じ長さで並べる。**
    `npm run check` の終わりがその一覧を出す（`scripts/not-checked.mjs`）。
    **その塊ごと写す。**要約しない。自分の言葉で書き直さない。

## 渡すとき

- **手元で落ちている、または確かめていないものを渡すとき、**
  そのまま渡して、再現や記録を相手に頼んだ。
  → こちらの仕事を渡していることになる。相手は使う側であって、試す係ではない。
  → **原因を潰してから出す。**

## 言葉を選ぶとき

- **相手が使っている呼び方があるとき、** こちらの都合で別の語に置き換えた。
  → 自分の言葉を否定されたように受け取られる。呼び方も二つに割れる。
  → **相手の語のまま呼ぶ。**訳語を作らない。
- **会話が圧縮された直後に書き始めるとき、** 覚えている型で書いて言語が戻った。
  → 同じことを何度も言わせる。
  → **目の前の発言を先に読む。**

## 指摘を受けたとき

- **指摘を受けて直すとき、** 何が悪かったかを考えないまま、形だけ作り替えた。
  （原文をやめて決め文句にする、など）
  → 同じ失敗が形を変えて戻る。相手は同じことを何度も言わされる。
  → **何が嫌だったのかを自分の言葉で言えるようになるまで**が直しの範囲。
- **仕組みや設計について言われたとき、** 目の前の作業の話としてだけ受け取った。
  → 答えが噛み合わず、言った側は伝わっていないことに気づけない。
  → **設計の話は、こちらの振る舞いの話でもあると考える。**
- **試験に書きにくいことを直すとき、** 書ける形（原文一致・表の網羅）に寄せた。
  → 形だけが残って、中身が残らない。
  → **汲み取れなかったことが見える印**を作って、そこを試験にする。

## 進め方を決めるとき

- **長い作業の途中で手が止まったとき、** 進み具合を出さず、次の声を待った。
  → 相手に叩き起こす仕事が増える。待っている時間も丸ごと無駄になる。
  → **自分から進み具合を出し、こちらから続きを始める。**
- **連続で回しているとき、** 1周ごとに同じ形の報告を書いた。しかも
  毎回「確かめていないこと」の一覧まで丸ごと写した。
  → **読む方には進捗が無い。**同じ文が並ぶだけで、そのぶんの token は
    利用者が払っている。金を取るために書いているように見える。
  → **回している間は黙る。**報告は最後に一度、まとめて。
    途中で言うのは、止まるとき（S1〜S9）と、聞かないと進めないときだけ。
    それも1周ごとではなく、**そうなった時だけ**。
- **連続で回す指示（`L=auto` の /auto-dev）で1周を終えたとき、**
  報告して手番を返した。**返した時点で止まる。**「次も続けます」と書いても、
  起こすものが無ければ何も起きない。
  → 相手が叩き起こすまで、何時間でも止まったままになる。
  → **報告より先に、次の起床を予約する。**予約してから書く。
    書いてから予約しようとすると、書き終えた時点で手番が離れる。
- **利用者が決めた制約（機材・環境・方針）が邪魔になったとき、**
  「やめては」と提案して、決めごとごと覆そうとした。
  → 事情を知らないまま、相手が決めたことを否定している。
  → **危ないところは伝えるだけにする。**前提を変えるのは利用者。
- **よく使う操作を画面のどこに置くか決めるとき、** 設定の奥に入れた。
  → 毎回探すことになる。見つからなければ無いのと同じ。
  → **普通の作法に合わせる。**参考にできるものが在るなら、まず見る。

## 直しが、別の壊れ方になるとき

- **既に動いているものに、新しい性質を足すとき、** 足した性質だけを試験にした。
  （名前の並び順を直したとき、順番だけを見て、**同じ名前を配らない**という
  元からの性質を見ていなかった。使い切ったあと全部同じ名前になり、
  **会話が上書きで消えた**。106 件作って 1 件しか残らない）
  → 直したはずが、前より悪くなる。相手は直った報告を受け取ってから壊れに遭う。
  → **触る前に、その関数がいま黙って保証していることを書き出す。**
    書き出したものも試験にしてから、新しい性質を足す。

- **自分が書いたものを確かめるとき、** 試す入力をこちらで選んだ。
  （字句器を手で選んだ16文で確かめて「一致した」と言った。無作為でぶつけたら、
  数は合っていたが**長い文で固まる**ことが出た。5万文字で 8.6 秒）
  → 通るものを選んだのと区別が付かない。相手は「確かめた」を信じて使う。
  → **入力はこちらで選ばない。**種を固定した無作為でぶつける。
    突き合わせる相手（本物の実装）が在るなら、それと比べる。

- **速さを検査にするとき、** 時間そのものを閾値にした。
  → 走らせる機械で結果が変わる試験になる。
  → **量を増やしたとき何倍になるかで見る。**二乗で書いていれば、
    5倍の長さで 25 倍前後になる。機械の速さに依らない。

- **後から起きることを検査にするとき、** 決め打ちで待ってから見た
  （`await setTimeout(200)` のあとに assert）。
  → 待ちが短ければ、機械が混んだときだけ落ちる。長ければ、**壊れていても
    通る**（まだ起きていないだけなのを「起きない」と読む）。どちらも、
    走らせる場所で結果が変わる。
  → **起きるまで見る／上限で諦める**に直す（`test/until.ts`）。
    上限で諦めるときは、開いたものを必ず閉じてから抜ける。
    閉じないと、落ちる代わりに**試験の走り自体が終わらなくなる**。

- **検査を足したとき、** 通ったことだけを見て足し終えた。
  → 落ちない検査は、無いのと同じ。守っているつもりだけが残る。
  → **わざと壊して、落ちることを確かめる。**終了コードまで見る。

## 手を動かすとき

- **動かしている別のものを止めたいとき、** `pkill -f` で文字列から探して殺した。
  → 自分の命令行にも当たって、その場で全部終わる（二度やった）。
  → **控えた PID を名指しして止める。**
- **変更が通るか確かめたいとき、** 手元で確かめられることを外の実行枠で回した。
  → 枠は実費で、使い切るとその日は何も確かめられない。
  → **手元で確かめる。**外で回すのは断ってから。
- **守らせたい決まりができたとき、** CLAUDE.md に文章で書いて済ませた。
  → 読まないので守られない。
  → **実行の手前で止める形にする。**
